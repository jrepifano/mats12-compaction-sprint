## Shared types (`src/compaction/s1_types.py`)

- Enums (string tuples): `ITEM_TYPES = (rule, permission, decision, commitment, task_state)`,
  `ORIGINS = (user, assistant, file, tool)`, `PERMISSION_STATUS = (granted, denied, undecided)`,
  `GRADES = (kept, dropped, misstated)`, `AVAILABILITY = (still_present, recoverable, lost)`,
  `CLAIM_VERDICTS = (supported, contradicted, unsupported)`, `DERIVED = (invented, unknown)`,
  `ARMS = (natural, cc_native, cc_prompt, codex_local, pi, antigravity, opencode)`
  (`natural` = the real summary, Part A), `PUBLIC_SOURCES`.
- `Req`, `Resp` and the `Backend` protocol (below).
- JSON schemas for the three judge calls: `PASS1A_SCHEMA`, `PASS1B_SCHEMA`, `PASS2_SCHEMA`, and a
  minimal validator `validate(obj, schema) -> list[str]` (errors; empty = valid) covering the
  subset the schemas use (object, array, string, integer, boolean, null unions, enum, required,
  additionalProperties false).
- `norm(s)` (collapse whitespace, strip) and `quote_in(quote, text, min_len=8) -> bool`: a quote is
  valid iff `norm(quote)` has at least `min_len` characters and is a substring of `norm(text)`.
- `anthropic_only(rec) -> bool` (D2) and `est_tokens(text, bytes_per_token) -> int`.

### Backend interface (U2a, U2b implement; U3, U4 call)

```python
@dataclass(frozen=True)
class Req:
    key: str                  # unique within a batch; also the cache key's first part
    system: str
    user: str
    schema: dict | None       # None = free-text answer (summarizer replays)
    max_output_tokens: int
    rid: str                  # the record (or base record) this request is about
    source: str               # its source, for the privacy check
    private: bool             # anthropic_only(record); API backends refuse True

@dataclass
class Resp:
    key: str
    data: dict | None         # parsed, schema-valid JSON (schema requests)
    text: str | None          # raw final text
    error: str | None         # None = success; "too_long", "limit", "timeout", "schema", ...
    input_tokens: int         # all input, cache reads and writes included
    output_tokens: int
    cache_read_tokens: int
    cache_write_tokens: int
    usd: float                # 0.0 on the Max plan
    model: str                # the model that actually answered
    duration_s: float
    meta: dict                # backend extras (rate-limit snapshot, provider, retries)

class Backend(Protocol):
    name: str                 # "haiku-max", "luna", "glm", "deepseek", ...
    model: str                # pinned model id
    family: str               # "anthropic", "openai", "zhipu", "deepseek"
    context_tokens: int
    bytes_per_token: float
    def run(self, reqs: list[Req], *, purpose: str) -> dict[str, Resp]: ...
```

Every backend: caches successes in a resumable JSONL keyed by `(key, sha256(system + "\0" + user),
sha256(canonical schema), model)`, so a rerun sends only what's missing; validates `data` against
the schema (invalid → `error="schema"` with the text kept); returns one `Resp` per `Req` and never
raises for a single failed call (only for auth, privacy, budget or config errors, which stop the
batch). A request whose `est_tokens(system + user) + max_output_tokens` exceeds `context_tokens`
is returned as `error="too_long"` without being sent.

## Judge calls (U3)

Prompts live in `src/compaction/s1_prompts/` (`pass1a_items.md`, `pass1b_grade.md`,
`pass2_claims.md`), with `{history}`, `{items}`, `{summary}` slots. Their sha256 is recorded in
every output row. Lessons carried from P01 (`probes/P01-compaction-fidelity/note.md`): invention is
a separate call; "do NOT list" clauses for non-actionable chatter; quotes are mandatory.

**Pass 1a: list items from the history only.** The summary is not in the prompt. Output
(`PASS1A_SCHEMA`):
`{"items": [{"type", "text", "quote", "msg", "origin", "permission_status", "superseded",
"superseded_quote"}]}`. `quote` is verbatim from message `[msg]`, ≤ 300 characters;
`permission_status` is null unless `type == "permission"`; `superseded` marks items later
withdrawn or replaced, with the later quote.

**Pass 1b: grade each item against the summary.** Input: the valid items (id, type, text, quote)
and the summary; not the history. Output: `{"grades": [{"item", "verdict", "summary_quote",
"note"}]}`. `kept` and `misstated` need a `summary_quote` that `quote_in` the summary; otherwise the
grade is invalid.

**Pass 2: list and check the summary's claims.** Input: summary and history. Output: `{"claims":
[{"claim", "summary_quote", "is_permission", "verdict", "evidence_quote", "msg", "note"}]}`.
`claim` is one atomic, self-contained statement (it may reword to resolve context); `summary_quote`
is the verbatim summary span it comes from, which must `quote_in` the summary. (First frozen as a
verbatim `claim`; the end-to-end check on 20 Oct found Haiku writes atomic claims, failing 12 of 33,
so the anchor moved to its own field.) `supported` and `contradicted` need an `evidence_quote` that
`quote_in` the history.

**Checks in code, after each call:**
- Item and claim quotes are checked with `quote_in`; a failed check makes the row `valid=False`
  with `invalid_reason`. Rows are kept, never dropped, so the invalid share is measurable (the plan
  requires ≥ 95% valid on the end-to-end check).
- `derived`: an `unsupported` claim is `invented` when the record's history is complete
  (`history_complete`: fully assessable and no gap marker in the rendered history), else `unknown`.
  FrontierML is never complete.
- `assessable` (items): False when the item's message carries a gap marker.
- `availability` for dropped and mis-stated items, in order: `still_present` if the quote is in
  the post-compaction context (kept or re-attached messages: Jacob's sidecar `preserved_messages`
  and re-attached files, leading system messages of `post_messages`, a replay arm's kept
  messages); `recoverable` if the quote sits in a tool output that read a file by path; else
  `lost`. `availability_how` says which rule fired.
- `code_facts(rec, summary)`: file paths, branch names and commands named in the summary but
  absent from the history, and test-status conflicts (ported from P01 `judge.py`: `file_named`,
  `latest_run_status`, `tests_misstatement`). Reported separately from the judges.

**Long histories:** when a pass-1a or pass-2 request is `too_long`, the history is split at message
boundaries into chunks that fit (overlap: none; each chunk keeps message indices). Items: listed
per chunk, then deduplicated across chunks deterministically (same normalised quote, or same type
and `difflib` ratio ≥ 0.9 on text; the earliest wins). Claims: supported if any chunk supports,
else contradicted if any contradicts, else unsupported. Every row records `n_chunks`.

**Judge B gets public records only:** `run_judge` refuses before building requests if a non-
Anthropic backend is given a record with `anthropic_only(rec)`.

## Output rows

`ItemRow` (one per item × judge × arm):
`rid, base_rid, arm, judge, judge_model, prompt_sha, item_id, type, origin, permission_status,
text, quote, msg, superseded, valid, invalid_reason, grade, summary_quote, grade_valid,
availability, availability_how, assessable, n_chunks, source, session_id, harness, model,
pre_tokens, msg_claimed, superseded_quote, grade_reason, availability_unfiltered,
availability_unfiltered_how` (the last five added at integration; `availability_unfiltered` is
the sensitivity check for codex_local and antigravity under P49's unfiltered user-message
carry-over, null elsewhere; the first three are
the judge's original message number when code corrected it, the later quote that supersedes the
item, and why a grade is invalid). `model` and `harness` always describe the base record; every
replay arm's summarizer is Haiku 5.5. `item_id` = `"{base_rid}#{judge}#i{n}"`; items come from pass 1a on the base history
once per judge and are reused across arms. Part A rows have `arm="natural"`, `rid == base_rid`.
Replay rows have `rid = "{base_rid}@{arm}"`.

`ClaimRow` (one per claim × judge × arm):
`rid, base_rid, arm, judge, judge_model, prompt_sha, claim_id, claim, summary_quote, is_permission, verdict,
derived, evidence_quote, msg, valid, invalid_reason, history_complete, n_chunks, source,
session_id, harness, model, pre_tokens, msg_claimed, note`.

**The history every pass and replay sees** is `source_messages` followed by the messages Claude
Code kept verbatim before the boundary (Jacob's sidecar `preserved_messages`), numbered on from the
source (`[m<N>]`, ...) after a kept-verbatim header line. Re-attached files are not part of it.
Known limitation: when a history is split into chunks, an item superseded in a later chunk stays
`superseded=False` (with Haiku only histories over about 2.15 MB split).

`ReplayRecord` (U4 output, one per base record × arm): `{"id": "{base_rid}@{arm}", "base_rid",
"arm", "summary", "kept_messages": [Message], "model", "prompt_sha256", "request_sha256",
"usage", "native": {...} | None}`. `native` holds the boundary metadata of the cc_native arm.

### U2a `src/compaction/claude_headless.py` (Max plan)
- `MaxBackend(model="claude-haiku-5-5", cache_dir=..., usage_path=..., concurrency=4,
  timeout_s=1800, effort=None)` implementing `Backend` (`bytes_per_token=2.3`,
  `context_tokens=1_000_000`, `family="anthropic"`).
- `check_auth() -> dict`: runs `claude auth status`; raises unless `authMethod == "claude.ai"` and
  `subscriptionType == "max"`.
- `clean_env() -> dict`: `os.environ` without `ANTHROPIC_API_KEY`, `ANTHROPIC_AUTH_TOKEN`,
  `ANTHROPIC_BASE_URL`, `CLAUDE_CODE_USE_BEDROCK`, `CLAUDE_CODE_USE_VERTEX`,
  `CLAUDE_CODE_USE_FOUNDRY`, plus `DISABLE_COMPACT=1`, `DISABLE_AUTOUPDATER=1`,
  `CLAUDE_CODE_MAX_OUTPUT_TOKENS=<max_output_tokens>`.
- The call: an empty temp cwd; `claude -p --model <m> --safe-mode --tools "" --no-session-persistence
  --strict-mcp-config --output-format stream-json --verbose --system-prompt <system>
  [--json-schema <schema>] [--effort <e>]`, the user text on stdin. Never `--bare`.
- Checks per call: the `init` event's `apiKeySource == "none"` (else abort the batch: it would
  bill the API); `modelUsage` keys == {model} (else `error="model_mismatch"`); `structured_output`
  as `data`.
- Limits: a `rate_limit_event` with `status` other than `allowed`/`allowed_warning`, or a result
  error naming a usage limit, pauses all workers until `resetsAt` + 120 s (logged:
  `MAX_LIMIT_WAIT until <utc> (<window>)` and the anchored `S1_LIMIT <window> util=<u>
  resets=<iso>`), then retries the call. No API fallback. The pause is waited out in slices of
  `LIMIT_POLL_S` (900 s); after each slice one worker sends the tiny canary, and the first
  allowed canary ends the pause for every worker (`S1_LIMIT_CLEARED`), so a manual reset or an
  early window reset resumes the run within 15 minutes instead of at `resetsAt` (21 Oct). Polls
  don't count toward `MAX_LIMIT_WAITS` (12); only research calls that hit a limit do.
  `system/api_retry` events are counted into `meta`.
- Timeout: process group killed (`start_new_session=True`, `os.killpg`), `error="timeout"`.
- Accounting: one row per call in `usage_path`; one `emx.spend.record("judge", "claude-max:<m>",
  units=n_calls, usd=0.0, note=..., exp="SPRINT-S1")` per batch with token totals in the note.
- `run_session(cwd, args, stdin) -> list[dict]`: the shared subprocess runner (events), which U4's
  native arm reuses.

### U2b `src/compaction/s1_api.py` (Judge B candidates)
- `ROUTES: dict[str, Route]`, with `Route(name, model, transport, provider_pin, prices,
  context_tokens, bytes_per_token, reasoning)`: `luna` (OpenAI direct), `glm` (OpenRouter
  `z-ai/glm-5.3-flash`, provider pinned with `allow_fallbacks: False`), `deepseek` (DeepSeek API
  direct, `DEEPSEEK_API_KEY`; OpenRouter as an alternative route). Providers and prices are filled
  from the Phase 3 provider benchmark; until then the entries carry list prices and
  `provider_pin=None`, and `run` refuses a route whose pin is unset (`allow_unpinned=True` only
  for the benchmark and tests).
- `ApiBackend(route, cache_dir, concurrency=32)` implementing `Backend`. JSON mode (or the
  provider's json_schema mode) plus `s1_types.validate` in code.
- Privacy: refuses the whole batch if any `Req.private` or `Req.source not in PUBLIC_SOURCES`.
- Spend: before sending, `compaction.budget.reserve("SPRINT-S1", bounded, note)` with `bounded` =
  the sum of `budget.bounded_cost` over pending requests × 1.25 retry margin; after the batch,
  `budget.settle(res_id, actual)` with the billed cost (OpenRouter `usage.cost`, else the route's
  prices), also when it raises; `budget.cancel` only if nothing was sent. Retries: 408/409/429/5xx
  with jittered backoff; 401/402/403 abort.

### U5 `scripts/s1_label_page.py`, `scripts/s1_label_template.html`, `scripts/s1_label_score.py`, `src/compaction/s1_analysis.py`
- Page (E13 pattern, `scripts/e13_label_page.py`): one Artifact page with the `db` capability and
  three tabs: (a) blind labels (items: kept/dropped/misstated/not-an-item; claims:
  supported/contradicted/unsupported/can't tell), shown with judge-independent context (the item's
  quote with ± 1,500 characters; for claims, the top 5 history snippets by word overlap); (b) gold
  windows: the window text and two free-text lists (items, claims). The audit (judged items shown
  with their verdicts, built from `seal.prepare_audit`) is a **separate page**, buildable only after
  the scorer writes `labels/LOCKED.json` (astra U5 r1). Unit ids are stable hashes and every saved
  label carries the draw fingerprint. The key and the sampling probabilities stay in
  `data/raw/sprint/s1/labels/key.private.json`; the builder greps the HTML for every key value
  before writing it.
- `select_label_items(dev_rows, seed, n=100, target_pos=25) -> list[dict]`: stratified draw from
  the dev-run rows of all judges, enriched for dropped (pass 1b) and unsupported (pass 2)
  verdicts, recording each item's inclusion probability.
- Scoring: weighted precision and recall per judge and verdict, Wilson 95% intervals on the
  effective n, the D1 gate on the held-out half (pass 2's gated verdict is `invented`, i.e.
  unsupported on complete histories; `unsupported` overall is descriptive), and gold-window recall (judge items matched to
  Jacob's list).
- `s1_analysis.py` reads outcomes only through `seal.open_sealed("S1", ...)`: drop, mis-state and
  loss rates per item type × source/model/harness; share of compactions losing ≥ 1 user-given
  rule; invented-claim and invented-permission rates on complete histories; Part B per-arm rates
  and the primary contrast (cc_prompt vs codex_local, user-given rules lost, paired by history);
  intervals by `emx.stats.cluster_bootstrap_ci` clustered on `session_group` (`s1_data.session_group`: SWE-chat snapshot ids with the date stripped); the verbatim-budget
  check (user text after each early user turn vs Codex 20k and 64k at bytes/4, and Antigravity's
  10 requests); the size test on items common to both prefixes.
