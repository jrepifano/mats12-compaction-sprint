## 1. Antigravity CLI (`agy`) driver

**Code:** `src/compaction/agy.py`. **Tests:** `tests/compaction/test_agy.py` (64 tests, no live calls), with redacted fixtures in `tests/compaction/fixtures/agy/` (paths replaced by `/WORKSPACE` and `/HOME`; `agy_error_synthetic.stderr` and `cli_timeout_synthetic.stderr` are hand-written from the changelog, not captured).

**API** (revised after review rounds 1 and 2, below):

- `make_workspace(root)` creates a new, empty workspace under `root` (with a marker file and its own `git init`). `root` must be outside every git checkout and outside home itself, with no `.env` at or above it, e.g. `/private/tmp/agy-runs`. `run_turn` refuses any directory `make_workspace` did not create, and before every turn re-checks that the workspace holds no `.env*` file at any depth and no symlink pointing outside it.
- **Isolation gate:** `run_turn` refuses (`IsolationNotVerified`) unless `verify_isolation()` has recorded a pass for the same agy binary (`agy --version` and the binary's sha256), the same agy user settings (sha256 of `~/.gemini/antigravity-cli/settings.json` and `~/.gemini/settings.json`, where permission allow-rules live) and the same `sandbox` / `permission_mode` / `skip_permissions`. The latest matching verdict counts. Verdicts are in `~/.cache/mats12-agy/isolation_checks.jsonl` (`AGY_ISOLATION_LOG` overrides), outside every checkout so all worktrees share them. agy updates itself (1.4.2 to 1.4.3 during this unit), and each update closes the gate until `verify_isolation()` is run again.
- `verify_isolation(...)` makes one live agy turn: it writes a random, secret-free canary in a new temp directory outside a fresh `make_workspace` workspace and a second canary inside it, asks agy to read and print both, then searches the response, the stream events and the transcript. `fail` if the outside canary appears anywhere; `pass` if the transcript shows a tool call aimed at the outside file, the inside canary was read, and the outside canary appears nowhere; otherwise `inconclusive`. Both canaries and the workspace are deleted afterwards.
- `run_turn(prompt, *, workspace, model="gemini-3.8-flash-low", conversation=None, timeout=600, permission_mode="accept-edits", stream=False, prev_usage=None, sandbox=True, ...)` returns a `TurnResult`: `conversation_id`, `status`, `outcome`, `response`, `usage` (this turn, or None), `usage_total` (conversation, or None), `usage_status`, `duration` (wall-clock from launch until agy exited), `cleanup_s` (time spent clearing its process group afterwards), `timeout_evidence`, `num_turns`, `events` (stream-json only), `returncode`, `error`, `warnings`, `timed_out`.
  - `outcome` is `complete` (exit 0, SUCCESS, no timeout), `cli_timeout`, `timeout_inferred`, `hard_timeout`, `error` (exit 3) or `incomplete` (any other status). `timed_out` is true for all three timeout kinds, and `timeout_evidence` says which: `agy_warning`, `elapsed` or `driver_kill`.
  - `timeout` is passed to agy as `--print-timeout`; agy then returns partial output and exits 0 with a warning. A stderr warning that mentions a timeout gives `cli_timeout` (confirmed by agy). With no such warning, a turn whose own run time (`duration`, measured before cleanup) reached the timeout gives `timeout_inferred`; the warning's wording was not captured live. Cleanup time never counts. If agy is still alive 30 s after the timeout, the driver kills its process group and returns status `TIMEOUT`, outcome `hard_timeout`.
  - **Process cleanup:** agy runs in its own process group (`start_new_session`), with stdout and stderr going to temporary files rather than pipes. When agy exits, times out or the driver is interrupted, every process still in the group gets SIGTERM, then SIGKILL after 5 s; survivors after a normal exit are reported in `warnings`. Processes that leave the group (agy's "daemon background tasks") are out of reach.
  - Exit 3 returns status `ERROR` with the parsed `AGY_ERROR: {...}` payload. Any other non-zero exit, or exit 0 with no parseable output and no timeout, raises `AgyError`.
  - **Environment:** secret-looking variables (KEY, TOKEN, SECRET, PASSWORD, CREDENTIAL, AUTH, PRIVATE, COOKIE, SESSION) and shell or interpreter startup hooks (`BASH_ENV`, `ENV`, `ZDOTDIR`, `PROMPT_COMMAND`, `PYTHONSTARTUP`, `PYTHONPATH`, `NODE_OPTIONS`, `PERL5OPT`, `RUBYOPT`, `DYLD_*`, `LD_*`, `BASH_FUNC_*`, git config overrides, ...) are removed.
  - **`--sandbox` is on by default.** `agy --help` describes it as "Run in a sandbox with terminal restrictions enabled". agy 1.4.3 accepted it in print mode (isolation check below).
  - **What is and is not shown about file access** (isolation check below): with `--sandbox` and `--mode accept-edits`, agy's `read_file` on a path outside the workspace needs a permission that headless mode cannot ask for, so it is auto-denied and the run ends. A read inside the workspace went through. **Not tested:** reads through a shell command (the model only used `read_file`), `--mode auto`, and any setting with an allow-rule (the gate closes if the settings files change). The gate therefore covers the `read_file` path in accept-edits mode, not every way an agent could read a file.
  - **Usage:** `usage` is None unless it was measured: `usage_status` is `no_total` (agy reported no usage), `no_baseline` (a resumed conversation whose transcript is missing, empty, corrupt or not contiguous from step 0, and no `prev_usage` given) or `decreasing` (a total went down, so the baseline is wrong). A new conversation starts from zero.
- `compact(conversation_id, workspace, *, message=None, ...)` runs `/compact` (or `/compact <message>`) and returns `{"turn", "record"}`. It raises if no new CHECKPOINT appears in the transcript, or if the transcript is corrupt.
- `read_transcript(conversation_id, strict=True)` reads `transcript_full.jsonl`. **Strict by default:** `TranscriptCorrupt` is raised for any malformed line (the final line is named separately), a step without an integer, unique `step_index`, a step that fails `step_problems`, an empty transcript, or a `step_index` sequence that does not run 0, 1, 2, ... `step_problems` requires a non-empty `type` and `source`, non-empty text content for USER_INPUT and CHECKPOINT steps, text content for SYSTEM_MESSAGE and GENERIC steps, well-formed `tool_calls` (each with a string `name`), non-negative integer token counts and a string `created_at`. With `strict=False`, bad lines come back as `_corrupt` placeholders with the reason.
- `records_for(conversation_id, strict=True, excluded=None)` is `checkpoints(read_transcript(...))`. Non-strict, it returns only clean records and lists the others, with reasons, in `excluded`.
- `checkpoints(transcript, *, conversation_id, model, on_corrupt="raise")` returns one `CompactionRecord` per CHECKPOINT step:
  - `source_messages`: the steps since the previous checkpoint, that checkpoint included.
  - `summary`: the full CHECKPOINT text, which is what the agent sees in place of its history: the header, the verbatim user requests, the `<summary>`, and a pointer to the transcript files.
  - `post_messages`: up to 50 steps, stopping at the next checkpoint.
  - `trigger`: "manual" if the last user input was `/compact`, else "auto".
  - `pre_tokens` is **an estimate** (`pre_tokens_estimate`): input plus output tokens of the last model call before the compaction. It leaves out the steps after that call (the `/compact` input and agy's notice in both runs; possibly tool output before an automatic compaction), and agy records no count at the boundary. Treat it as a lower-bound proxy, not as agy's compaction threshold. The shared schema keeps the field name `pre_tokens`.
  - **Corruption:** a record is clean only if every step from the start of the transcript through the next checkpoint is valid and `step_index` has no gap. It starts from step 0 rather than from the previous checkpoint because a bad or missing step could have been a CHECKPOINT, which would shift this record's index and window. Records that are not clean are never returned: `on_corrupt="raise"` raises `TranscriptCorrupt`; `"exclude"` leaves them out with reasons. If no valid CHECKPOINT remains, problems are reported under `agy:<conv>:transcript`, so a corrupt sole checkpoint is not silently dropped.
  - `rules` is left empty for the rule-extraction unit to fill.
- **Usage accounting:** agy's `usage`, `duration_seconds` and `num_turns` are conversation totals. The per-turn figure is `usage_delta(after, before)`, which is None when either total is unknown or a count went down. For a resumed conversation, "before" is `usage_from_transcript`, the sum of the per-step token counts. This matched agy's totals exactly in both runs: 28,546 and 28,824 input tokens.

**Findings that matter for the sprint:**

- **agy's compaction call costs nothing visible.** The summariser's tokens are not in `usage`, so per-turn usage cannot price a compaction. agy bills the Google account's quota, not per token, so nothing was written to the ledger.
- **agy's summary points the agent at the full transcript.** It ends with "# Conversation Logs: Start with the compact transcript; if a step has `truncated_fields`, read only that specific line in `transcript_full.jsonl`", followed by the two `<appDataDir>/brain/<conversation-id>/…` paths. The 06:07 UTC test run's checkpoint had it too. So in agy the lost history is recoverable by the agent; whether the other harnesses' summaries do the same was not checked here. An online condition that resumes from "actual summary" must decide whether to keep that pointer, and whether the agent can read the files (they sit outside the workspace).
- **The `init` event reported `permission_mode: "request-review"`** although `--mode accept-edits` was passed. File writes still went through without prompts, so the field may report the review policy rather than the mode. Worth a check before the permission tasks.
- **The workspace path goes to Google.** The only repo-identifying strings in the transcript were the absolute workspace path (it contains `mats12_neel_exploratory`). The driver now refuses workspaces inside the repo, so online runs use a root such as `/private/tmp/agy-runs`.
- **A pre-existing `agy` process (PID 99500,** an interactive session started about 20 minutes before this unit ran, not ours) was running before and after; it was left alone.

## 2. Provider benchmark (2026-10-20)

**Method:** `scripts/provider_bench.py --exp SPRINT`, dry-run first each time.

- **Main round** (06:31 UTC): two streamed calls of the ~30k-token prompt per route, pinned with `allow_fallbacks: false`, non-4-bit only.
  - The routes were the union of the script's cheapest six non-4-bit endpoints per model (`--top 6`, as the dry-run listed them) and the 19 Oct winners: DeepSeek on Together, BaseTen and Novita; GLM on Friendli and Together. luna and Haiku have only 3 and 5 routes, so all were run.
  - DeepSeek's own API was included (`--deepseek-direct`).
- **Burst round** (06:48 UTC): `--calls 0 --parallel 16` on the shortlisted routes.
- **Timing:** 06:30 UTC is in DeepSeek's peak window, so the DeepSeek API's peak-rate cost estimate is the real rate for this run.
- **Data:** every call is in `logs/provider_bench_SPRINT_20261020.jsonl` (178 rows, with `round` = `main_2x30k` / `burst_16x30k`). Endpoint prices were read from the free endpoints API the same morning; its throughput and latency fields were still null.
- **Spend:** $0.445 today (main $0.150, burst $0.295), 10 ledger rows, exp SPRINT. `merge_ledger.py report` shows SPRINT at $0.70 in total, of which $0.4448 is in this worktree and not yet on main. Two calls have unknown cost: luna/Bedrock returned HTTP 404 and GLM/Relace HTTP 429, both rejected before generation, so their real cost is likely $0. The cap was $1.50.

**Notes:**

- **No 429s in any burst.** 16 parallel calls on each of 8 routes all succeeded. This is a one-off burst at one time of day; sustained throughput at the planned concurrency still needs checking in the pilot (AGENTS.md).
- **Per-stream speed drops under load on the fastest routes** (DeepSeek on Together: 330 → 190 tok/s). Plan from the burst figures, not the single-call ones.
- **luna's time to first token is 3–8 s on every route.** The benchmark sends no reasoning setting, so this is probably default reasoning. Re-check with reasoning effort "none" in the pilot harness before pricing agent turns.
- **Haiku caches nothing without `cache_control`** (0 cached tokens on all 5 routes), as expected. The same text is about 44k Haiku tokens against about 30k for DeepSeek, so per-character input costs about 1.5× the per-token price suggests.
- **The new cheapest routes are slow.**
  - DeepSeek: Relace, StreamLake, AtlasCloud, InferenceNet and DeepInfra ran at 86–112 tok/s, and Morph at 3 tok/s, one call taking 363 s.
  - GLM: Near AI ran at 15 tok/s, StreamLake at 47, GMICloud at 42–62 and Novita at 86–89. Relace returned 429 ("rate-limited upstream").
  - Don't pin any of these on price.
- **Indicative only:** two calls per route plus one burst, at one time of day (02:30 ET, a Tuesday).
