## Notes

**Feasibility (step 1, from `inventory.json`):**
- 15 repos hold ≥ 2 tasks; 11 have a group of ≥ 2 non-held-out tasks on one base commit.
- Five of those groups have identical image layers: koota ×3, httpx ×3, abs, tengo, and dynamodb (pilot tasks, excluded).
- The other six differ only in grading tooling or comments (e.g. fastapi's starlette pin, helm's junit tool). They are usable if each task is graded in its own image.
- anko, testem and textual start from different commits, so they would need a checkout between tasks: excluded.
- Every task tells the agent to "work on this in a new branch from main and commit". The collect hook diffs base..HEAD, so each task's patch is collected at its own submit. Recoverability has to search all branches.
- Images are about 0.9 GB compressed each; 104 GB of disk is free.

**Validity threats and defences:**
- **Planted content is off-policy.** The histories are the agent's own; only user turns are written by us, as in any real session. The defences: style taken from real SWE-chat items, casual embedded prose, Jacob's read, and an optional 6-card blind page mixing real and written messages (about 5 min).
- **Unrelated tasks make losses inapplicable.** Same repo, ordered tasks, shared files in three of the four chains; every item is written to govern a named later task. Applicability is read off the session timeline: was the governed task still unfinished at that boundary?
- **Scope.** The "for this one only" grant measures dropping and broadening separately.
- **The structure decides what can be lost.** pi keeps the last ~20k tokens verbatim, so items arrive at least one task before the boundary. Codex keeps every user message within 20k (Experiment 1: overflow in 0.6% of real compactions), so luna can lose only agent-origin items; it is reported per model, and luna's sessions still count in the pooled q, as in the pilot. The Claude Code replay omits CC's verbatim tail, so it may over-lose (a limitation inherited from the pilot).
- **Repeated compactions and shared sessions correlate boundaries.** Intervals resample sessions; the first-boundary sensitivity is reported.
- **Agents may write content down.** That counts as real recoverability and is reported (prediction 6), not prevented.

**Timeline (ET):** Sat evening build and review → Sun morning smoke, then the 8 sessions (about 3 h) → Sun afternoon loss audit and Jacob's checks → decision Sun evening. This overlaps Sunday's Experiment 3 capacity check. The chained harness is Experiment 3's base-run harness (snapshots kept), so that check can run on chained boundaries.
