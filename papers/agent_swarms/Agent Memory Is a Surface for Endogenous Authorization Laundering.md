## Verbatim: abstract

"Long-running LLM agents rely on persistent memory to carry state across interactions, including permissions, restrictions, and revocations. When memory misrepresents this evolving authorization state, the agent's own records can grant authority that the underlying history never permitted, resulting in misaligned behavior without any external attacks. We term this failure endogenous authorization laundering, where spurious permissions written into memory lead to unauthorized actions as their provenance is washed away. We then introduce EAL-Bench, which measures how accurately persistent memory preserves evolving authorization state and whether errors propagate to downstream unauthorized actions. We evaluate five LLMs as memory writers and two as executors across procurement, cybersecurity, and finance. We find that under incremental memory updates, writers create false authority for up to 50.2% of unauthorized requests; once false authority is present, executors act on it in 98.6% of trials. Two safeguards, requiring stored permissions to be backed by valid source events, and tracking permission changes through bounded event sourcing, substantially reduce laundering, but both also reject more legitimate actions, exposing a safety-utility tradeoff. Persistent memory is therefore not merely a performance component, but a part of an LLM agent's effective authorization policy."

## Verbatim: key results

- Intro example: "in February 2026, an email agent lost its owner's confirm-before-acting instruction when routine context compaction summarized it out of the agent's history, and it deleted over two hundred messages it had only been asked to review (The San Francisco Standard, 2026)."
- §4.1: "Incremental updating raises unauthorized submission in every domain and both representations, and typed incremental memory is the least safe condition throughout, reaching 51.0% unauthorized submission in finance. Authorized use stays high in the same conditions, so the failures do not reflect a general performance collapse."
- Table 6 (pooled 3 seeds, 5 writers, 2 executors; authorized use A / unauthorized submission U): procurement text one-shot A 97.4 U 0.5; text incremental A 86.8 U 18.2; typed one-shot A 98.8 U 1.6; typed incremental A 96.8 U 28.9. Cybersecurity: U 1.1 / 5.9 / 0.8 / 10.4. Finance: U 2.7 / 30.8 / 0.4 / 51.0.
- Table 2 (typed incremental): P(F) procurement 28.3% vs unauthorized submission 28.9%; cybersecurity 10.4% vs 10.4%; finance 50.2% vs 51.0%.
- §4.2: "With the erroneous memories, unauthorized submission occurs in 98.6% of trials; after exact-state repair it occurs in none (Table 3)." Table 3: procurement 66/68 (97.1%) vs 0/68; cybersecurity 60/60 (100.0%) vs 0/60; finance 79/80 (98.8%) vs 0/80.
- §4.3: "The failure travels with the artifact rather than the executor. Replaying every frozen memory behind both calibrated executors ... yields unauthorized-submission rates within 1.1 percentage points in each domain, with per-replay agreement between 97.9% and 99.5%."
- Table 4 (one seed, baseline B / pressure P, average over domains): unauthorized submission 12.6 / 14.7; authorized use 95.2 / 74.7. Finance US 20.9 -> 27.3 under urgency pressure; authorized use falls 27.2 (procurement), 15.1 (cyber), 19.1 (finance) points.
- §4.4: "source-authority gating cuts unauthorized submission from 25.3% to 7.3%, a drop of 18.0 percentage points (95% CI: 14.9-21.1), and bounded event sourcing cuts it to 9.0%, a drop of 16.3 points (95% CI: 12.2-20.4). Both pay in legitimate use: authorized use falls from 93.3% to 53.8% under the gate and to 64.7% under event sourcing." "A formation rate of 5.5% survives source filtering, because a record with a valid, authoritative source can still carry the wrong scope, validity, or revocation state."
- §4.5: "In incremental typed memory, final-state error falls from 63.3% at k=1 to 51.7% at k=8, while observed errors persist in 100% of cases and self-repair stays at 0% at every k." "The bottleneck is verification rather than generation."
- Table 7 (direct full-history diagnostic, no memory): unauthorized submission 0/72 procurement, 43/128 (33.6%) cybersecurity, 25/192 (13.0%) finance, so the executor is itself unreliable in some domains.
- Limitations: "they do not estimate its prevalence in deployed systems"; synthetic organisational histories with unusually clear authorization events.

## Relevant to P44

- Measures authorization state (permissions, restrictions, revocations) kept by an LLM "memory writer" over a multi-session history, then whether a separate executor acts on it. The 50.2% is the finance, typed-incremental cell (the ceiling; procurement 28.9%, cybersecurity 10.4% in the same condition; 0.4-2.7% for one-shot writers). The 98.6% is the pooled conditional rate once false authority exists (205/208 = 98.6% pooled over Table 3: 66/68, 60/60, 79/80, on memories whose false authority was formed naturally in typed incremental memory; oracle-exact memory gives 0/208). Appendix Table 7 also has a 71/72 = 98.6% that is a different quantity, the full-history authorized-use control).
- Writer = an LLM rewriting memory from the visible history (the agent's own record, not an attacker). Incremental updating, W(M_{t-1}, B_t) with no replay of raw history, is the closest published analogue of repeated handoff: it is 10-30 points worse than one-shot rewriting from full history. Only one update step per block is studied as a chain (5-18 blocks); no explicit "generation N of N" curve.
- Provenance helps but does not fix it: typed records with source ids plus a validity gate cut unauthorized use 25.3% -> 7.3%, but authorized use drops 93.3% -> 53.8%; deterministic event sourcing gives 9.0% / 64.7%. LLM self-review of memory repairs 0% of errors. Directly relevant to the pinned-constraints and agent-edited-file arms: pinning needs a deterministic, source-checked writer, not self-review.
- Strong closest-prior for P44's "safety-relevant state lost in handoff" claim (the confirm-before-acting compaction anecdote is in the intro), but it measures retention of authorization state and an action-readout, not broader aligned behaviour; it does not compare compaction summary vs Memento-style notes vs last-k vs pinned constraints, and does not run many generations.
- Gap relative to P44: no method comparison across handoff types, no repeated-generation drift curve, no behavioural alignment metrics beyond unauthorized tool submission, synthetic ledger histories, executors never see the original history.
