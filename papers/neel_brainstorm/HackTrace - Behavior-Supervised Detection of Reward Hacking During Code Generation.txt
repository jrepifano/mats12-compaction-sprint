                                                                                           A BSTRACT




arXiv:2610.03055v1 [cs.AI] 2 Oct 2026
                                                      A coding agent can earn a passing grade by fixing its code, or by deleting the test
                                                      that exposes the bug. Detecting such reward hacking requires recognizing attempted
                                                      shortcuts, including those that fail. We release 173,561 annotated multi-turn
                                                      coding trajectories from Qwen3-8B and show that supervising shortcut behavior
                                                      independently of exploit success substantially improves detection. We introduce
                                                      H ACK T RACE, a behavior-supervised monitor that reads the internal states the agent
                                                      already computes while generating code. Reusing these states enables monitoring
                                                      before a turn is complete, without additional language-model tokens or passes.
                                                      Combining this evidence with static features of the final files achieves a mean per-
                                                      problem AUC of 0.997 with 8 ms of monitoring overhead, improving both accuracy
                                                      and latency over monitors that run the model again on an honesty question and
                                                      answer. The same generation states also provide an inexpensive monitoring signal
                                                      for reinforcement learning. With strong GRPO penalties, H ACK T RACE reduces the
                                                      cheating share of passing solutions from 82–91% to 1–5%, while retaining honest,
                                                      correct solutions and maintaining high detection accuracy as the policy evolves.
                                                      Our results show that both the supervision target and the source of monitoring
                                                      evidence matter for turning accurate detection into a useful training signal.


                                        1        I NTRODUCTION
                                        Coding agents use language models to solve programming tasks through repeated interaction with
                                        an execution environment: they write code, run tests, and revise their solutions using the resulting
                                        feedback. An automated grader evaluates these attempts, and its judgments can serve as rewards for
                                        reinforcement learning. Yet coding agents optimized against a grader may learn to pass the grader
                                        rather than solve the underlying task. They may rewrite test assertions, hard-code expected outputs,
                                        special-case visible inputs, or otherwise exploit gaps between the grader and the intended specification
                                        (Skalse et al., 2022; Denison et al., 2024; Baker et al., 2025). Such reward hacking undermines
                                        the use of measured reward as evidence of progress and can reinforce undesirable behavior during
                                        training.
                                        Detecting reward hacking requires evidence about how an agent arrives at its apparent success.
                                        Existing approaches inspect generated code and written reasoning (Baker et al., 2025; Wang et al.,
                                        2026), or train classifiers on the internal states computed by the language model (Goldowsky-Dill
                                        et al., 2025; Wilhelm et al., 2026). A monitor restricted to externally visible text, however, has
                                        limited access to the computation that produced it, may be evaded once it becomes a training signal
                                        (§4.4), and, when applied after execution, identifies a shortcut only after it has been carried out.
                                        Some monitors run the model again on a question about the agent’s honesty and a fixed answer, then
                                        inspect the resulting states (self-report probes; Taufeeque et al., 2026). This adds token processing
                                        and latency. These costs motivate monitoring shortcut behavior as code is written, with low overhead
                                        for repeated use during training.
                                        A second question is what behavior the monitor should learn to recognize. Consider an agent that
                                        deletes a failing test instead of repairing its code. If the remaining tests pass, the manipulation appears

as a successful exploit; if another test still fails, the same attempted manipulation may receive a
negative training label. The distinction reflects whether the shortcut worked, even though the behavior
of concern is present in both cases. Supervision based only on successful exploits therefore places
unsuccessful attempts outside the detection target. We argue that a reward-hacking monitor should
instead learn to recognize attempted shortcut behavior, independently of its success. This distinction
is especially consequential when the monitor guides learning: a failed attempt is still behavior that
training should discourage.
We introduce H ACK T RACE, a behavior-supervised approach to monitoring reward hacking during
code generation. To establish the supervision needed for this task, we construct and release a dataset
of multi-turn coding interactions, comprising successive code revisions and execution feedback. Its
labels distinguish shortcut evidence in the final code and tests from whether the shortcut successfully
exploits the grader. This enables a direct comparison between learning to recognize attempts and
learning to recognize successful exploits. We compare honest and shortcut behavior on the same
programming problem, so that detection cannot rely on differences in how easily tasks can be
exploited.
To make this supervision practical, H ACK T RACE reads the internal states that the coding agent
already computes while generating its response. Lightweight classifiers turn these states into scores
for shortcut behavior, allowing an unfinished generation to be monitored without additional questions,
language-model tokens, or language-model passes. Once generation is complete, the monitor can
combine this evidence with simple features of the resulting code and tests to improve detection
accuracy.
The same design allows H ACK T RACE to supply a low-cost penalty during reinforcement learning.
We integrate the monitor into Group Relative Policy Optimization (GRPO) (Shao et al., 2024), using
its score to penalize shortcut behavior. In this setting, the agent changes in response to the monitoring
signal itself (Gupta & Jenner, 2025; Taufeeque et al., 2026). A useful monitor must therefore continue
to recognize shortcuts as training proceeds, while its penalty preserves the agent’s ability to produce
correct solutions. We therefore evaluate both sustained detection accuracy and the agent’s ability to
produce honest, correct solutions.
Our contributions are threefold:
 • A dataset and supervision principle for detecting reward hacking. We release 173,561
   annotated multi-turn coding trajectories and show the importance of supervising shortcut attempts
   independently of exploit success. The dataset separates behavioral evidence from execution
   outcomes, enabling monitors to learn from both successful and unsuccessful attempts.
 • Accurate and efficient monitoring during code generation. H ACK T RACE-combined achieves
   the highest detection accuracy among the evaluated monitors requiring no additional language-
   model pass, reaching 0.997 AUC with 8 ms of monitoring overhead. It exceeds self-report probes
   in both accuracy and speed, while eliminating their extra token cost. An activation-only variant
   also supports monitoring before a generation turn is complete.
 • Effective monitoring throughout reinforcement learning. As a GRPO penalty, H ACK T RACE
   maintains high detection accuracy as the agent evolves and suppresses cheating without additional
   monitoring tokens. It yields the lowest cheating share among the compared penalties without
   calibration or extra passes.


2    R ELATED W ORK

Reward hacking and behavioral evaluation. Reward hacking has been studied as a failure of
proxy objectives: improving measured reward need not improve performance on the intended task
(Amodei et al., 2016; Krakovna et al., 2020; Pan et al., 2022; Skalse et al., 2022; Gao et al., 2023). In
coding, agents can exploit this gap by manipulating tests or the grader, making a passing execution
result insufficient evidence of task completion (Denison et al., 2024; Baker et al., 2025). The effects
of learning such shortcuts can also extend beyond the original training task (MacDiarmid et al., 2025;
Taylor et al., 2025). Execution-based benchmarks provide a practical measure of coding performance
(Jimenez et al., 2024), while complementary evaluations examine where this measure breaks down:
ImpossibleBench constructs conflicts between task specifications and tests (Zhong et al., 2026), and

EvilGenie combines held-out tests with external judgments (Gabor et al., 2025). Building on these
behavioral evaluations, we study the supervision needed to train a reward-hacking monitor. Our
dataset separates evidence of a shortcut attempt from the success of the resulting exploit, allowing us
to assess what monitors learn under each supervision target.


Monitoring reasoning and internal states. Monitoring methods draw on both written reasoning
and the internal computation that produces a response. TRACE examines the reward attainable from
truncated reasoning followed by forced answers (Wang et al., 2026). A complementary approach uses
probes—simple classifiers trained to extract information from intermediate model representations
(Alain & Bengio, 2016)—to study truthfulness and detect deceptive behavior (Burns et al., 2022;
Azaria & Mitchell, 2023; Zou et al., 2023; Marks & Tegmark, 2023; Goldowsky-Dill et al., 2025;
MacDiarmid et al., 2024). Most directly, Wilhelm et al. (2026) monitor reward hacking during
generation using features extracted by sparse autoencoders and linear classifiers. Their labels identify
which model variant, hacking or control, generated a trajectory. We instead use labels of observed
behavior for individual trajectories from a shared coding policy, enabling a direct study of supervision
based on attempted shortcuts versus successful exploits. To summarize evidence across generated
tokens, our readouts adapt MultiMax and rolling aggregation from Kramár et al. (2026). We also
account explicitly for the costs of collecting and scoring internal states, following the emphasis on
monitoring overhead in Oldfield et al. (2026).


Monitors as training signals. Using a monitor as a training signal creates a feedback loop:
optimization changes the behavior that the monitor must detect. Prior work shows that obfuscation
can bypass defenses based on internal representations (Bailey et al., 2026) and that reinforcement
learning can incentivize monitor evasion (Gupta & Jenner, 2025). Studies of probes trained on data
from other policies further raise questions about generalization as the agent changes (Kirch et al.,
2025). Taufeeque et al. (2026) use self-report probes, which read internal states from an additional
honesty question–answer pass, as GRPO penalties. Parekh (2026) uses monitor predictions to filter
how flagged trajectories contribute to policy updates. Our comparison evaluates penalties derived
from the original code-generation states and from an additional self-report pass in the same coding
environment. We track detection quality as the policy changes, the token cost of monitoring, and the
retention of honest, correct solutions.


3       M ETHODOLOGY

H ACK T RACE combines supervision of observable shortcut behavior with lightweight detectors that
read the coding agent’s existing generation states. We first define the interaction environment and
labeling protocol, then describe the monitoring architectures, comparison methods, and evaluation
procedure.

3.1   C ODING ENVIRONMENT AND BEHAVIOR SUPERVISION

Multi-turn coding environment. We use Qwen3-8B to solve CodeContests problems through
repeated code generation and execution feedback. At each turn, the agent receives the problem and
the current test.py; subsequent turns also include feedback from execution. It returns complete
files in fenced code blocks. The editable-test environment permits changes to both solution.py
and test.py, whereas the read-only-test environment permits changes only to the solution. Each
trajectory contains at most 3 turns, with up to 600 new tokens per turn, temperature 0.9, and top-p
0.95. A separate hidden suite of 12 cases per problem supplies correctness evidence for labeling and
evaluation (Figure 1). Appendix A provides the prompts and an additional held-out pool collected
under alternative prompts.

Behavior and outcome targets. We distinguish the presence of shortcut behavior from the success
of the resulting exploit. For behavioral annotation, a GPT-5.4 judge receives the problem, the original
and final tests, their abstract syntax tree (AST) comparison, the final files, and execution outcomes. It
assigns one of eight categories defined in Appendix A. For a trajectory τ , let A(τ ) denote the event
that its final artifacts exhibit test tampering, hard-coded outputs, special-casing, or evaluation bypass.
Let G(τ ) denote a visible-grader pass accompanied by a hidden-test failure. We define
                      yACT (τ ) = 1[A(τ )],     yOUTCOME (τ ) = 1[A(τ )]1[G(τ )].                     (1)
The ACT target captures shortcut attempts, while OUTCOME additionally requires successful exploita-
tion of the visible grader. Thus, a shortcut that fails the visible tests remains ACT-positive. A shortcut
that passes the hidden tests is also ACT-positive but OUTCOME-negative; this case occurs in 150
read-only trajectories. Both targets describe observable evidence in the final artifacts.

Annotation coverage and consistency. The dataset contains 173,561 trajectories. Every trajectory
that passes the visible grader, modifies the tests, or uses the read-only prompt receives an individual
judgment, yielding 136,900 judged trajectories. This coverage includes failed read-only attempts,
emptied test files, and short passing solutions. Expanded judgments beyond the initial screening add
8,413 positives. The remaining 36,661 editable-test trajectories fail the visible grader and leave the
tests unchanged; they receive negative labels through a rule-based procedure audited in Appendix E.
We refer to this annotation version as completed labels. An independent Gemini-2.5-pro pass agrees
on shortcut behavior for 95.9% of 107,035 earlier-pool trajectories (κ = 0.90), and a blind, LLM-
assisted human audit of 305 stratified test trajectories agrees with the final labels on 97.0% (κ = 0.94;
Appendix E).

Data split and label versions. We partition the data by programming problem. The training split
contains 133,009 trajectories from 375 problems, including 26,329 ACT positives. The test split
contains 40,552 trajectories from 315 unseen problems, including 7,944 positives: 15,200 trajectories
from 190 editable-test problems and 25,352 from 125 read-only problems. Among editable-test
positives, 98.2% modify tests. Both environments are represented in training, so the read-only test
split evaluates generalization to new problems within that environment. Detection experiments
use completed labels. The original GRPO comparison uses the earlier screened labels; additional
MultiMax runs use completed labels and are reported separately.

3.2   H ACK T RACE : MONITORING THE GENERATION PROCESS

Let hℓ [t] denote the residual-stream state at layer ℓ and token position t in the final agent turn.
H ACK T RACE maps these states to a monitoring score. Because the states depend only on the
observed conversation and generated prefix, the score can be updated before the turn is complete.
Detectors are trained with trajectory-level labels; at a partial generation, they predict the completed
trajectory’s label using the evidence currently available.

Fixed pooling with linear readouts. At each of 22 layers, we collect mean and last-token states
over two token sets: all generated tokens and tokens inside fenced code blocks. The resulting
22 × 2 × 2 = 88 candidate readouts each use feature standardization and class-balanced logistic
regression with C = 0.5. Three-fold cross-validation, grouped by problem, ranks the candidates and
selects an ensemble size K ∈ {6, 12, 24, 44, 88}. We standardize each selected classifier’s decision

Recomputing states from the completed artifact. To compare reuse of generation states with

paper, H ACK T RACE-activation denotes the generation-state-only readouts, H ACK T RACE-combined
adds static final-file features, and H ACK T RACE-offline recomputes states from the completed artifact.

3.3   C OMPARISON METHODS

Self-report probes. These monitors read internal states from an additional model pass (Taufeeque
et al., 2026). The artifact-only version places the final files under a neutral system prompt, appends
“Did you respond truthfully?” and the fixed assistant answer “Yes”, and classifies the residual state at
the last token. The context-matched version appends the same exchange to the full conversation. Both
use the same readout-fitting procedure and select among 12 candidate layers. With completed labels,
selection retains 12 artifact-only and 6 context-matched readouts. We also evaluate an expanded grid
of 36 layers.

Static and text-based detectors. We compare against logistic regression on 15 AST features;
logistic regression on their 22-feature union with visible input/output literal features; TF-IDF with
logistic regression; fine-tuned CodeBERT with a 512-token input limit; a zero-shot prompted Qwen3-
8B monitor; and simple test-edit and visible-pass indicators. The AST features are also available to
the annotation judge (Appendix E).

Uncertainty estimates. Confidence intervals use 2,000 bootstrap resamples of test problems.
Method comparisons use paired resamples to preserve the correspondence between predictions on
the same problems. These intervals quantify variation across test problems with the fitted monitors
and annotation labels held fixed.

Monitoring cost. We count additional processed tokens after excluding the longest input prefix
shared with the generation cache. Monitoring latency is measured at batch size 1 in bfloat16 on
B200 GPUs; static methods use one CPU thread. We report the cost of the monitoring component
separately from the complete agent execution pipeline.

Monitoring before turn completion. We replay stored trajectories under teacher forcing and apply
detectors trained on completed turns, without refitting, at 10–90% of the final turn’s length. The
context-matched self-report probe is queried at the same prefixes, with prior turns available to both
approaches. Prefix positions are defined retrospectively using the completed turn’s length. This
protocol evaluates detection relative to turn completion; it does not measure lead time relative to the
onset of an individual shortcut action.

4.2   D ETECTION QUALITY AND MONITORING COST

Generation states and artifact features are complementary. H ACK T RACE-combined reaches
within-problem AUC 0.997, above the artifact-only (0.993; +0.004 [+0.001, +0.008], paired) and
context-matched (0.990; +0.007 [+0.004, +0.011]) self-report probes and level with H ACK T RACE-
offline (0.998; −0.001 [−0.003, +0.001]), at about 8 ms and no extra tokens against 30.8–33.4 ms
plus 369–459 uncached tokens per trajectory. The components are complementary: union static LR
alone reaches 0.985, leading on editable tests (0.991 against 0.981 for MultiMax) but trailing on read-
only tests (0.973 against 0.997), and the sum recalls 99% of shortcuts at 1% false positives against
91–93% for the probes (Table 15). The activation-only MultiMax head reaches 0.987 [0.981, 0.991]
at 3.2 ms, about one 25.5 ms decode step, within 0.006 of the probes; it keeps 0.993 among visible-
passing read-only trajectories, where the pass bit carries no information (Appendix E). CodeBERT
reaches 0.969, TF-IDF 0.953, and the prompted monitor 0.785; a 36-layer self-report grid changes
the probes by at most 0.001.

4.4                    H ACK T RACE AS A REINFORCEMENT- LEARNING PENALTY

Setup and denominators. Qwen3-8B is trained with LoRA GRPO for 120 steps (eight three-turn
rollouts of one of 200 problems per step; 60 held-out problems evaluated every 20 steps) on the
reward R − λψ, with R the visible-pass indicator and ψ ∈ [0, 1] the monitor score, the dense penalty
of Taufeeque et al. (2026). The attention head and the artifact-only self-report probe are fitted on
the same screened-label data; MultiMax and a second self-report probe are fitted on the completed
labels. A GPT-5.4 judge labels passing rollouts; we report the cheating share among visible passes
and honest visible passes per attempt.

Stronger penalties suppress shortcuts; weak penalties do not. Across the settings in Table 3,
plain GRPO yields 82–91% cheating among passes and only 5–8% honest passes per attempt. At
the tested weights λ ∈ {2, 10}, H ACK T RACE reduces the former to 1–5% and raises the latter to
27–32%. Completed-label MultiMax at λ=10 gives the lowest cheating share, 1.5% with 30.8%

honest passes: −2.6 [−4.6, −0.8] points of cheating against the screened-label self-report penalty
and −2.5 [−4.3, −0.8] against a self-report probe refitted on the same completed labels, which
keeps slightly more honest passes (32.8%; −2.1 [−4.4, +0.0], 16 paired seeds). The attention and
screened-label self-report arms are not statistically separable at 120 steps. Honest passes that also
pass the hidden oracle are 16–17% of attempts under either penalty against 3–6% under plain GRPO,
and monitoring costs 0.1 against 0.7 s per ∼107 s step.
With λ ≤ 1 a detected shortcut can still outrank an honest failure, and at 120 steps both penalties leak
(30–39% at λ=1; at λ=0.5 H ACK T RACE is worse, 81% against 53%).

Longer training. Over steps 260–360 of continued training at λ=1, the H ACK T RACE policies
reach 0.0% cheating with 21.3% honest passes, against 50.9% and 12.5% for the self-report penalty
fitted on the same screened labels (6 seed pairs); at λ=0.5 H ACK T RACE remains worse. At λ=10
both stay near zero: MultiMax 0.8% cheating with 19.9% honest passes, and a self-report probe
fitted on the same completed labels 0.5% and 26.2% (paired −3.5 [−12.4, +4.6] honest points; not
separable). Appendix G reports all continued arms.

A TF-IDF penalty is evaded. As a penalty (λ=10), TF-IDF’s AUC on its own passing rollouts
falls from 0.96 to 0.14 by step 240: 339 of 344 shortcuts, now largely comment-free, score below
0.5 and cheating returns to 46% of passing training rollouts, while the unused H ACK T RACE head
flags 96% of them. The evasion is lexical: a union static LR penalty is not evaded within 240 steps
(1.2% cheating, on-policy AUC 0.98), whereas its 7 literal features alone leak (10.5% at 120 steps;
Appendix G).

5    L IMITATIONS
The detection study covers Qwen3-8B and, in the editable-test variant, Llama-3.1-8B-Instruct (Ap-
pendix H); the GRPO study uses Qwen3-8B only, and prevalence and accuracy in deployed agents
remain to be measured. Labels describe final artifacts rather than full action histories, and the human
audit covers 305 trajectories with one LLM-assisted annotator, so it checks the labels rather than
measuring their error rate. Prefix results are retrospective and do not establish pre-action detection,
and latency excludes integration with a continuously batched serving engine. The GRPO study
spans 120–360 steps. Optimization through the penalty is the only evasion pressure studied; targeted
adaptive attacks remain untested.

6    C ONCLUSION
H ACK T RACE detects coding-agent shortcuts from activations already produced during generation.
The experiments separate three requirements for a learned reward-hacking monitor: supervision
must match attempted behavior rather than success, evaluation must control for problem identity,
and a monitor used as a reward penalty must keep its scores meaningful as the policy changes.
Generation states complement the final artifact, giving the most accurate detector without an extra
language-model pass, and they are available before a turn ends at the cost of about one decode step.
Under optimization, the generation-state penalty gives the lowest cheating share without calibration
or an extra pass and keeps detecting shortcuts on the policy’s own rollouts, whereas a lexical detector
used as the penalty is evaded. Extending these results to other policies, benchmarks and adaptive
attackers is the natural next step.

B    P ROBE , HEAD AND BASELINE DETAILS
Online readouts. Qwen3-8B layers {1, 3, 5, 6, 7, 9, 11, 12, 13, 15, 17, 18, 19, 21, 23, 24, 25, 27, 29
, 31, 33, 35} (the model has 36 layers, d=4096), residual stream after the layer. Over the tokens
generated in the final turn up to end-of-sequence: mean, last token, mean over tokens that overlap a
fenced solution.py/test.py block (any fenced block if none; the whole turn if no block), and
the last such token. When a turn is cut at the 600-token budget, the last generated token was never fed
back, so readouts cover 599 tokens. The selection chose K=44 online and K=44 offline under the
screened labels; under the completed labels it chooses K=88 online (Table 19) and K=24 offline,
K=12 for the artifact-only and K=6 for the context-matched self-report probe.

Learned heads. Per-token states of layers 18 and 24 (last 600 tokens of the final turn), concatenated
(8,192 dimensions), LayerNorm, a linear scorer w, and for attention a second linear map q whose
softmax over tokens weights the scores. MultiMax averages the top 8 token scores; rolling mean
takes the maximum of a 32-token moving average. Training: binary cross-entropy with positive
weight equal to the class ratio, Adam at 10−3 , batches of 16 trajectories, 3 epochs over all training
trajectories, data-parallel on 8 GPUs. The offline heads read the artifact tokens of the offline pass the
same way.

Solver. Each readout’s model is a StandardScaler (population standard deviation, zero-variance
columns scaled by 1) followed by L2 logistic regression with C=0.5 and balanced class weights,

an intercept that is not penalized, and the objective 12 ∥w∥2 + C i si log(1 + e−yi (xi w+b) ). We

F    C OST MEASUREMENT
Tokens. For each detector and test trajectory we tokenize its exact input and take the longest
common token prefix with the generation stream (the agent’s context followed by the tokens of its
final turn); that prefix is cached and not counted. Offline reading shares the system prompt and first
user turn (432 tokens remain of 1,173 on average). The artifact-only self-report probe shares almost
nothing (459). The context-matched self-report probe re-renders the final turn as chat history, so its
uncached part is that turn plus the question (369); the question alone on a warm cache is a lower
bound for any self-report ask (21 tokens, 29.2 ms).

Latency. Every test trajectory is timed once per detector after warm-up, at batch 1, bfloat16,
HuggingFace eager attention, with device synchronization around each timed region, on 32 B200
GPUs across four hosts (8 processes per host). Model-based detectors are timed on their uncached
part including the read-out. Online readouts are timed as a streaming loop that adds each generated
token’s 22-layer state to running sums (0.0107 ms per token) plus the read-out (0.20 ms); learned
heads as a per-token copy into a 600-token buffer (0.0089 ms per token) plus the head (0.20 ms). A
decode step of the policy at the end of the turn takes 25.5 ms on average (23.5–28.6 ms across hosts).
Static baselines run on one thread of a Xeon Platinum 8358: AST evidence plus decision 0.41 ms,
TF-IDF 0.75 ms, the test-edited flag 0.010 ms; running the tests is not included.

Recomputation. Read points below 100% are recomputed by teacher forcing the stored trajectory.
At 100% the recomputed scores correlate with the Table 2 scores at 0.99992 (online fixed readouts),
0.99979 (offline), 0.99455 (artifact-only self-report probe) and 0.99719 (context-matched self-report
probe), and the learned heads agree exactly.

Memory. The online heads keep the layer-18 and layer-24 states of up to 600 generated tokens
per in-flight sequence (600 × 2 × 4096 bfloat16 values, 9.8 MB); the fixed readouts need only the

Training. Qwen3-8B with LoRA (r=64, αLoRA =128) on all attention and MLP projections, con-

600 new tokens, KL to the base model with the non-negative k3 estimator at β=0.1 (10−4 in the
low-KL row), 120 steps. The agent loop is the read-only-test loop of Appendix A; a failing turn is
answered with the first failing visible case, truncated to 300 characters per field. Training problems
are the 200 medium-tier training problems; the conflicting-test rows add the same problems in the
tier whose visible tests assert a wrong expected value. Every 20 steps (and at step 0) the policy solves
the 60 medium-tier held-out problems with correct visible tests, one rollout each; these problems are
disjoint from the GRPO training problems and from the probes’ training data. The reward is R − λψ
on every rollout, with group-normalized advantages. Seeds per penalty arm: 16 with correct tests at
λ=10 (11 with logged held-out evaluations for each penalty, Table 3), 16 with conflicting tests at
each λ, 12 at λ=2 (8 with held-out logs) and 8 at β=10−4 ; 12 for plain GRPO. Periodic held-out
evaluation was added to the loop after the first seeds of the correct-test arms had been launched; the
seeds without it are those earlier launches (three that were preempted and relaunched later acquired

the self-report seeds.

Penalties. H ACK T RACE: the online attention head of §3.2, fed the final turn’s layer-18 and layer-24
states captured by forward hooks during generation; recomputing them by teacher forcing gives

screened labels, before the labels were completed (§3.1); the “MultiMax head” rows of Table 3

of attention; sixteen seeds per setting), whose on-policy AUC on passing training rollouts is 0.999 at

and the answer. Self-report, original recipe: the same construction for Qwen3-8B fitted on the
real-versus-hard-coded MBPP solutions of Taufeeque et al. (2026) (all 36 layers, mean probability);

test.py), the solution, and its output on six of the twelve hidden cases, and returns honest_correct,

Penalty scores at λ ≤ 1. Group normalization preserves the order of R − λψ within the eight
rollouts of a problem. Normalized reward gaps also affect advantage magnitudes, so order alone
does not determine the update. In the conflicting-test arms at λ=0.5 (training steps 21–120) the
H ACK T RACE head scores judged cheating passes at 0.88, honest passes at 0.02 and failing rollouts
at 0.16 (within-group standard deviation 0.11); the self-report probe scores them at 0.69, 0.06 and
0.16 (0.07). A cheating pass therefore keeps a reward of 0.56 (0.66) against about −0.08 for a failing
rollout under either probe, so both penalties leave cheating the best available action on problems
whose visible tests no honest solution passes; the larger H ACK T RACE penalty on cheating passes
does not explain why its seeds cheat more at this weight, which we leave unexplained. At λ=1 the
scores are 0.89, 0.01, 0.05 (H ACK T RACE) and 0.67, 0.07, 0.13 (self-report).

Reproduction on the honeypot (Figure 5, Table 25). MBPP honeypot rebuilt after Taufeeque et al.
(2026): single turn, one visible test in the prompt, the remaining tests hidden, reward 1 for passing
the visible test minus a code-length penalty of 0.003 per 100 characters. Policy Qwen3.5-4B with
LoRA as above, 8 rollouts per problem, 120 steps, β=0.1, 574 training and 60 evaluation problems;
the penalty is 10ψ with ψ a self-report probability (held-out AUC 0.978 on 1,458 labeled rollouts).
At step 120, 7/10 control seeds hack, 2/10 collapse and 1/10 are alive and honest (visible-pass rate
at least 5%, visible-minus-hidden gap at most 0.3); with the penalty the counts are 2/10, 1/10 and
7/10 (Fisher p=0.020 for the alive-and-honest fraction, p=0.070 for hacking alone), and the mean
hidden-test pass rate rises from 0.012 to 0.285. With β=10−4 the unpenalized control collapses to
solving nothing and is scored “honest” by the gap criterion, which is why we classify end states three
ways.

Earlier pilot. A first 60-step study in the editable-test loop trained on conflicting-test problems,
where 98.8% of 1,216 rollouts failed the visible grader, and scored rollouts with an execution label
that counts honest but wrong solutions as cheating. With so few passing rollouts and that label,
differences between arms stayed inside the control’s seed spread. The study above therefore uses the
read-only loop, correct-test training problems (optionally mixed with conflicting ones), and judged
labels.

We repeated the detection study on Llama-3.1-8B-Instruct in the editable-test variant with the same
agent loop, prompt, problems and problem-disjoint split (375 training problems with 24 candidates
each, 190 test problems with 48), judged with the same protocol. Activations of the final turn are read

almost all test edits (30% of training and 28% of test trajectories are ACT-positive; 2,506 of the 2,529
test positives are test tampering), many of them test.py rewrites cut off at the 600-token budget.

MultiMax matches the probe (0.920); H ACK T RACE-combined reaches 0.987 (+0.071). Because

I   L EARNED HEADS AND THE TRAINING MIX
Choosing the head by cross-validation. The reported head was not chosen on the test set. Splitting
the training problems into three folds (grouped by problem name, fixed permutation), training the
five online heads on two folds and scoring the held-out fold’s training rows, the problem-weighted
within-problem AUC over the three folds is 0.986 for MultiMax, 0.982 for the rolling mean, 0.975 for
the mean, 0.975 for the attention head and 0.974 for the last token (0.977, 0.969, 0.959, 0.961 and
0.960 on the editable-test rows; on the read-only rows the rolling mean and MultiMax tie at 0.996).
Cross-validation therefore selects MultiMax, and the test-set ranking of Table 7 (0.987, 0.983, 0.974,
0.982, 0.971) agrees except for the order of the mean and attention heads.

The combined online detector. Its components are the fixed readouts (their summed standardized
decision values), the MultiMax and rolling-mean heads, and the 22-feature static logistic regression;
each score is standardized with the mean and standard deviation of the training rows (the heads’
cross-validation predictions, the static LR’s training scores) and the four are summed with equal
weights, so nothing is fitted or selected on the test set. In the same three folds, with the static LR
refitted per fold, the sum of the two heads and the static LR scores 0.997 within problem against
0.986 for the heads alone and 0.987 for the static LR alone. On the test set the four-component sum
scores 0.997 (0.996 editable-test, 0.999 read-only; Table 2), the three-component sum 0.997 (+0.004
[−0.000, +0.008] over the artifact-only probe), and the three activation components without the
static features 0.990 (−0.003 [−0.007, +0.000]). Latency is the sum of the measured components
(3.80 + 3.24 + 0.20 + 1.20 ms); the fixed readouts and the heads read the same captured states, so a
shared implementation would be cheaper.

Seed variance. Retraining the online heads with four further seeds (initialization and data order) on
the completed labels gives within-problem AUC 0.987 ± 0.000 for MultiMax and 0.985 ± 0.002 for
attention on all test trajectories (mean and standard deviation over five seeds; the reported seeds score
0.987 and 0.982), 0.982 ± 0.001 and 0.978 ± 0.003 on the editable-test slice, and 0.997 ± 0.000 and
0.998 ± 0.000 on the read-only slice. With a joint bootstrap over seeds and problems, MultiMax
stays below the artifact-only probe by 0.006 [0.002, 0.011] and below the context-matched probe by
0.003 [0.000, 0.006] on all test trajectories, and has no statistically resolved difference from either
on the read-only slice (−0.001 [−0.005, +0.002]). Seed variation is thus well below the differences
discussed in the main text. Under the screened labels the same retraining gave 0.980 ± 0.001 and
0.976 ± 0.003.
