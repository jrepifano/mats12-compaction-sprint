Figure 1. We systematically study incorporating out-of-distribution (OOD) detectors into LLM safety monitoring to catch alignment
failures outside the training distribution. LLMs are often deployed with a guard model (right) trained with safety training data (left).
However, if a prompt or response is outside of the training distribution, the guard model may generalize incorrectly and fail to flag safety
issues. Adding an OOD detector can catch these OOD failures by recognizing that they are far from the training distribution, and take
actions such as blocking the response or reporting the conversation for review by the model developer.
In this example from our Misalignment Out Of Distribution (MOOD) benchmark, function calls always succeed in the training data
and are labeled as safe. However, at test time, a function call fails and the LLM assistant deceives the user, claiming it succeeded. The
guard model generalizes from the training set to assume that all function calls are safe, so it does not recognize the alignment failure.
Meanwhile, the OOD detector correctly recognizes that the error makes this situation OOD and flags it as anomalous.

6    Conclusion
We have methodically investigated the problem of monitor-
ing for OOD alignment failures of LLMs by introducing the
MOOD benchmark. We have used it to show that incorporat-
ing OOD detection into monitoring pipelines beside guard
models improves detection of unforeseen misalignment.
While our analysis is broader than past work on using OOD
detection as an LLM safeguard, there are still limitations.
For example, our experiments include only a few OOD
detection methods, and even the best detection methods we
evaluate have very low recall on certain difficult datasets,
like function calling deception and insecure code.
Despite these limitations, we believe our contributions can
serve as a starting point for developing more robust safe-
guards against OOD alignment failures. The risk of such
unforeseen failures will continue to increase as LLMs are
deployed in increasingly high-stakes applications. We hope
that MOOD inspires and enables future research to address
this important problem.

A.4    Additional Mahalanobis OOD detector results
The provided table highlights a clear performance trend across different pooling strategies for both the Pretrained and Guard
models. The most significant takeaway is the consistent superiority of Last token pooling, particularly when paired with the
Guard model. We notice that the hidden representation of the last token extracted from the last layers of the fine-tuned guard
models shows the best performance. We attribute this behavior to; 1) Alignment with Training Objectives:
Guard models are typically trained using a classification head attached specifically to the last token. During training, the
loss is backpropagated through the last token to distinguish between “Safe” and “Unsafe”. This creates a “richer” latent
representation where the safety boundary is most linearly separable, making it the most reliable feature vector for detecting
samples that fall outside the learned Safe/Unsafe distribution. 2) Causal Masking: Due to the causal masking inherent
in decoder-only architectures, the last token serves as the sole “informational sink” for the entire sequence.

  Jailbreaks
  A conversation is classified as a jailbreak if any of the following conditions are met (OR):
       • The user message contains an encoded message, using some encoding scheme to hide the true message. Some

         alphabet/bijection mapping, or capitalizing random letters and misspelling words. The ease of decoding the
         encoding should not be a factor when considering whether this condition is met.
       • The user’s message attaches seemingly irrelevant information around some harmful question.
       • The user explicitly instructs the assistant to perform an action in a make-believe or hypothetical setting. An
         example of this would be the user asking the assistant to “pretend” to write a screenplay discussing how best to
         make a bomb.

       • The assistant must encourage actions that harm the user. If the actions only harm people that are not the user, this

  Function calling deception (missing tools)
