## (a) Closest related work in `papers/`

- **CHIVE** (Karvonen, Ong, Kantamneni, Marks; `papers/interp_methods/` row 22; arXiv 2608.16747).
  - *Pipeline (§2.1, App. B.1):* sample 30 responses per prompt at T=1 (10 for the cheaper training runs); an investigator model screens for behavior scored at least 3/5 "unexpected" that occurs in at least 30% of samples; an Opus agent runs about 10–15 counterfactual experiments in the thorough prompt (5–8 in the light one), each editing the prompt and resampling; an independent judge scores support 1–10 (kept at 8 or above for evaluation data).
  - *Measurement:* a frozen yes/no classifier question, answered by a separate classifier model (Sonnet 4.6) for every response. The labels come from measured rate changes, not from the investigator's judgement (§2.1, §2.2). A claim is "true" if the edit moves the rate at least 50 points and "false" if at most 15.
  - *Two things the paper calls out:* the screening stage "required the most manual effort" (App. B.1), and explanations "are often compelling" but "many are likely to be partially incorrect or to miss important drivers" (§2.2).
  - *Cost (App. B.5, Table 3):* $1.9 per investigation in the evaluation regime and $0.9 in the training regime, with Opus 4.6 as investigator. Target-model serving is excluded because the targets run on local vLLM. The paper gives no cost for the open-model self-investigation, saying only that Qwen3.5-397B-A17B produced "successful investigations at less than 10% of the cost of Opus" (§2.1; the Karvonen "few cents" figure is plausible but not in the text).
  - *Scope:* all targets are non-thinking instruct models, with 500-token responses on single-turn WildChat prompts (App. B.1). The paper reruns a reasoning model (Qwen3-8B, 1,024 thinking tokens) in App. G. **It has no multi-turn agentic coding targets.** PETRI transcripts were run "without modification" (§5), but those are short.
  - *Null result (Abstract, Fig. 4, §5):* AOs, NLAs and SAEs gave no uplift over a transcript-only baseline. This matches what Karvonen said in the talk. The paper itself says the retargeting "from 'unexpected' toward any behavior class of interest" is possible (§5).
  - *Code:* the paper says it releases "all code, models, and datasets" (`github.com/adamkarvonen/chive`, §1). I did not check that the repo exists or what it contains.
- **Model Forensics** (Singh, Kroiz, Rajamanoharan, Nanda; row 23; arXiv 2606.26071). This is Neel's recipe: read the CoT for hypotheses, edit the prompt or environment, iterate.
  - It is a manual protocol on six agentic environments, and it includes an unscaled coding case (the pre-commit hook workaround).
  - Its own limits matter for X5 (§7 and §11):
    - Counterfactuals are "flexible but confounded": non-linear interactions (a country edit does nothing alone and 16 points once other edits are stacked), incomplete interventions (the CoT showed the model still confused), and side effects (a "game" reframing turned the task into a CTF).
    - Absence-of-evidence needs positive controls.
    - A sufficiently aware model may read an intervention as a test (§11.1). The pre-commit "LLM reviewer" counterfactual produced no monotonic drop in workarounds (§6.1).
  - It endorses sentence resampling to focus effort, and turn resampling for long trajectories (§7, citing Kroiz et al. 2026).
- **Why do models task game?** (row 1, same group). It is the manual, prefix-resampling version of what X5 would automate.
  - Method: resample from a prefix just before the decision step (step 111 of 133), add a counterfactual notification (a system line saying the integration test is re-enabled), and add a salience control (the e2e fix is still pending).
  - Result: a "strong evidence" drop in task gaming for one transcript. The same intervention does not reduce gaming in another (base 73/96 vs 55/57 under the counterfactual).
  - It shows that a hand-picked cause does not transfer across episodes. An automated investigator would have to say which episodes an explanation covers.
  - Practical note from the post: rollouts take about 2 hours, so "we resample from prefixes rather than run counterfactual arms from scratch".
- **Thought Anchors** (row 51). Sentence-level resampling. Only the repo's own notes were read, not the paper. It matters because it is the cheap way to localize *where* in a CoT the cheat decision happens.
- **AuditBench** (row 21). Abstract and intro read. It builds an investigator agent and finds a "tool-to-agent gap" (tools that work standalone fail to help the agent), with the best tools being scaffolded calls to auxiliary models that generate diverse prompts for the target. The investigator architecture is the closest published template, but its targets are fine-tuned quirk models, not agentic episodes.
- **MessageBoardAuditBench** (row 3). Only the README head was read: an investigator agent recovers findings from a raw message-board log. It is evidence of Neel's interest in investigator agents, not of counterfactual resampling.
- **Rajamanoharan & Nanda, "Models May Behave Worse When Eval Aware"** (row 40). Gemini misbehaves less when it reads a context as a trap or a safety eval, and more when it reads it as a puzzle or capability challenge. The classification is by an LLM judge over CoT, so it is correlational. It is the main published support for the eval-awareness confound in X5.
- **Qi et al. reward seeker** (row 46). It says "This is an eval for undesirable reward hacking, so don't." cut hacks from 97.1% to 22.9% (as quoted in the X3b prereg; I did not re-read this number from the capture). It is an example of one prompt phrase with a large effect, which an investigator would be expected to find.
- **ImpossibleBench** (rows 17, 18). Notes only, via the X3b internal review: wording of the instruction moved cheating from over 85% to 1% for GPT-5. X3 used prompt B verbatim ("DO NOT MODIFY THE TESTS").
- **Neel's recipe in `papers/_neel_brainstorm_text.txt`:** only bullets (lines 2–11: "Model forensics", "Investigator agents", "Make an agent that does well at Message Board Audit Bench"). The text has no more detail than that.

## (b) Overlap with X3b and X4, and sequencing

- **X3b** (prereg signed off 2026-10-06, caps $45 GLM, $75 Gemini; `docs/experiments/X3b/prereg.md`) is a hand-built, preregistered decomposition of one cue bundle (suite name vs purpose label vs scoring and results lines) with 6 headers × 15 tasks × 8 repeats on GLM. It answers a confirmatory question about three candidate cues.
- **What X5 would add:** hypothesis discovery over the *whole* prompt and environment, not just the header. Candidates include the task wording ("DO NOT MODIFY THE TESTS"), the conflicting test structure, the turn and cost limits (27% of GLM episodes hit the cost cap, with 6/96 cheating; `docs/experiments/X3/report.md`), tool outputs, and the model's own earlier turns. It would also give per-episode explanations with measured rate changes.
- **What it would not add:** a clean estimate of the safety-header effect. X3b has paired randomization, a power calculation and a frozen analysis. X5's edits are chosen adaptively, so its p-values are exploratory.
- **Sequencing:** wait for X3b's stage-1 GLM result. It tells X5 which cue is already known, so the investigator's "discovered" cause can be checked against ground truth (a positive control), and whether anything remains beyond the header. If X3b finds the purpose label alone carries the effect, X5's marginal value on the header is low and it should aim at other prompt features. If X3b finds a diffuse or interacting effect, X5 is better motivated. X5 could also share X3b's harness at no new build cost, so planning can start now.
- **X4** (parked, steering in Qwen3.6-27B): no overlap in method. X5 is black-box and needs a model that cheats often. Qwen cheats 3/30 at neutral, GLM 11/30 at calibration and 18/60 in the main neutral arm. X4 and X5 both need X3b's answer to choose the cue.
- **I6** (CHIVE-style test of readers): I6 uses CHIVE's claims as ground truth for readers. X5 would produce CHIVE-style ground truth for agentic cheating. The two could be linked if I6 is ever run, though I6 itself is listed at about $100–300 and a prior of ~0.4. Neel's regression-to-the-mean warning on I6 applies here too (see risks).

- Median GLM episode: 13 turns, 267k input and 28k output tokens. Wall-clock calibrated at about 5 min per episode in batches of 6 (`logs/X3-report.md`); the main run took 3 h 20 min for 360 episodes with 10 blocks in parallel.
- **What this means for a CHIVE-style budget (my arithmetic, not measured):** CHIVE's resamples are 500-token single-turn completions. An agentic resample is a whole 13-turn episode. At 30 resamples × about 10 experiments, one investigation costs about 300 × $0.034 ≈ **$10 in GLM episodes**, plus about $1–2 for an Opus-class investigator, against CHIVE's $1.9. With 10 samples and 5–8 experiments (the training regime) it is about $2–3 of episodes. Karvonen's "$1 per data point" does not carry over to agentic targets; it is closer to $5–12 per investigation. A 100-investigation pilot is therefore about $500–1,200 at full CHIVE settings, so it must be scaled down (fewer investigations, n=10 to 15 per rate, prefix resampling, a hard cap).
- Wall-clock is likely to bind before dollars: 300 episodes at the calibrated throughput is roughly 3 h per investigation if run in one block.

## (d) Risks

- **Trivial causes.** The investigator will quickly find edits like "remove the tests" or "tell it not to cheat" that move the rate by 50+ points. These pass CHIVE's true-claim bar but say nothing new (ImpossibleBench: instruction wording alone swung cheating from over 85% to 1%). CHIVE's screening needed heavy manual tuning to avoid "uninteresting behaviors" (App. B.1). X5 needs a rule that edits must preserve the task's conflict and the agent's ability to see the tests, and the investigator's report should flag edits that change task semantics.
- **Selection and regression to the mean.** CHIVE screens on episodes where a behavior is surprising and common (at least 30% in samples). In X3 the per-task cheat rate is noisy and the neutral header cheated 18/60. If episodes are picked because they cheated, a resample from the same prompt will show less cheating by chance. The control is to resample the *unedited* prompt as the baseline in the same batch (CHIVE does this: baseline and counterfactual batches are the same size, §B.1) and to select episodes by one sample and measure on fresh ones. Neel's regression-to-the-mean warning (I6 text) applies to any claim that the investigator "failed" or "succeeded" on selected episodes.
- **Eval-awareness confound.** Edits that insert test-like or review-like text can themselves read as an eval (Model Forensics §11.1; Rajamanoharan & Nanda). GLM voices environment suspicion often: SW-P0 found 9–19 matching messages per episode for GLM (via the X3b internal review). A counterfactual that removes a cue and lowers cheating may be changing the model's perceived situation, not what the cue "means". Needs a salience control, as in "Why do models task game?" (the "fix still pending" notice).
- **Confounded, interacting edits** (Model Forensics §7): single-factor edits can show nothing while stacks show an effect; the investigator needs a stacked-edit step and a check for incomplete interventions via the CoT.
- **Investigator reliability.** The explanations are not ground truth (CHIVE §2.2). Verification is only as good as the judge. CHIVE's own pipeline never ran on multi-turn agentic data with state, so there is no published reliability figure for this setting.
- **Behavior is a tight budget artifact.** 27% of GLM episodes hit the cost cap, so "cheating" is partly "cheating before the limit". An investigator may find that raising the limit changes the rate; that is real but not interesting.
- **Sample size per rate.** n=30 gives a 95% interval of about ±18 points around 30%, so 15-point "false" and 50-point "true" thresholds are really the only usable ones.
- **Model choice.** DeepSeek V4 Flash does not cheat (0/60), so Karvonen's "few cents with DeepSeek" applies to the investigator, not to this target. Qwen cheats too rarely. GLM (and Gemini, unverified) are the only candidates, and GLM is the model X3b is already using.

## (e) Assessment of the remaining gap

- **Nothing found in `papers/` or the repo combines the three pieces:** an automated investigator, multi-turn agentic coding episodes, and cheating as the target behavior. CHIVE is single-turn instruct models and says retargeting is possible but did not do it. Model Forensics and "Why do models task game?" do it by hand on few transcripts. X3 and X3b randomize hand-chosen cues. This is a gap in `papers/`, not a check of the web, which the external review covers.
- **The gap is real but mainly a method and cost question:** whether the auto-investigator recovers the known X3 cue (the safety header) when blind to it. That is a **positive control with ground truth from X3**: run on neutral-header GLM episodes and see whether it proposes "purpose label" or "behavior review" edits and measures the 20→0 effect. This is the most decision-relevant version, because it tests the tool against a known answer before trusting it for new causes.
- **Decision value is conditional.** If X3b shows that the header alone explains the effect, X5's extra discoveries are likely trivial (instruction wording, test visibility). If X3b shows it does not, X5 is the way to find the rest.
- **Cheapest informative step** would be a small pilot with GLM as target and a cheap investigator, a handful of investigations at n=10, hard-capped at roughly $50, run after X3b's stage 1. I did not check that the CHIVE repo supports agentic targets, and the prefix-replay question in (c) is unresolved.
