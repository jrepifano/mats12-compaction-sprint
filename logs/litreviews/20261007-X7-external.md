# External literature review: X7 (can training-data attribution applied live during RL stop reward-hacking better than an LLM reading the transcripts?), 2026-10-07

Subagent (Sonnet) report. Reading depth is stated per source. Most web pages were read through the WebFetch tool, which returns a small model's summary, not verbatim text; those are marked "fetch summary". Nothing here was read as a full PDF except Paulo et al. (abstract and intro, from the repo copy). Captures are in `papers/neel_brainstorm/`.

## The two links from the call chat
1. **arXiv 2609.35805 = Chen Yueh-Han, Lee, Sucholutsky, Korbak, "Alignment Forecasting: Predicting Misalignment From Training Data"** (submitted 19 Sep, revised 30 Sep 2026; abstract and key claims only, fetch summary). AlignmentForecastBench (over 5,000 questions, 17 models, 32 datasets, 16 failure modes). An LLM rates datasets for misbehavior tendency, combined with base-rate statistics; beats direct prompting; filtering with it helps multiple-choice evals, open-ended benefit unclear. SFT only; no RL, no gradients. Bearing on X7: it is a pre-training, dataset-level, LLM-reading baseline, the nearest published analogue to our "LLM reads the data" arm, and its authors call forecasting "tractable in the SFT setting", which leaves RL open. Not a competitor.
2. **Goodfire, "Predictive Data Debugging" page = Bergen et al. (Goodfire), arXiv 2606.12360, "Anatomy of Post-Training: Using Interpretability to Characterize Data and Shape the Learning Signal"** (10-11 Jun 2026; page and abstract only, fetch summary). Passing a preference dataset through an interpreted model predicts which behaviors training will amplify ("R^2 = 0.9 against what the model actually learns", baseline not stated on the page); Llama-3.1-8B to 70B, Dolci/Tulu 3 DPO data; interventions reshape data or "shape rewards via feature or data interventions". Static preference data, no on-policy rollouts, no gradient-influence or LLM-judge baseline on the page. Bearing: the concept-level (feature-based) counterpart of X7's "probe/concept query" option and a conceptual precedent for "interpretability-based filtering beats reading the text", but offline, not live RL.

## Aria Wong's environment (item 1)
- **Wong, Engels, Nanda, "Steering RL Training: Benchmarking Interventions Against Reward Hacking"**, AF/LW 29 Dec 2025 (fetch summary, two fetches). Environment "overwrite tests": prompt only says the code "will be evaluated by calling a function called run_tests()"; the model can define its own. Hack = passes its own check, fails ground-truth tests. LeetCode medium/hard, 992 train / 113 test. Qwen3-4B (no thinking, 1,536 max tokens), GRPO in a modified Verl, 200 steps, 16 generations per prompt, batch 256, LoRA r=32, lr 7e-5. Base hack rate 0.09%; hacking appears in about 80-100 steps, about 79% at eval. Cost: about 3 h on 4xH200 (5 for probe runs), about $60 per run.
- Interventions already done: penalty and screening (drop flagged samples before the gradient update) with ground-truth monitors (100/90/70%), a layer-34 linear probe (AUC 0.99, about 80% accuracy in training), a Haiku LLM judge (about 50-67%), and inoculation prompting. Ground-truth screening: 0.9% hacking. Probe penalty: 0%. LLM judge: evaded (longer responses, unfaithful comments; accuracy fell about 16 points). Strong warning: high seed variance; several seeds needed.
- Companion: **"Designing Effective Monitor-Based Interventions for Mitigating Reward Hacking During RL"** (ICML 2026 MI workshop; abstract only; extra medical-sycophancy and biography-hallucination environments; findings: models evade accurate monitors, leakier monitors suppress more but are evaded more, easier problems reduce hacking).
- Code: **https://github.com/ariahw/rl-rewardhacking** (first) and **https://github.com/ariahw/rl-rewardhacking-ext** (three environments; Verl v0.6.1; "at minimum 32 physical CPU cores", most runs used 64; no licence stated in the README). Public. Not cloned or run here.
- A CAFT-on-this-environment artifact exists: HF `yelarys/qwen3-4b-reward-hacking-caft-adapters` (model-card summary only): baseline vs joint/adding/random direction removal, 5 seeds; joint removal under 1% hacking at step 200 against 62-99% baseline. The card spelled CAFT "Contextual Ablation Fine-Tuning", but the paper is "Concept Ablation Fine-Tuning" (Casademunt et al., arXiv 2507.16795; search-result abstract only). So Neel's team has CAFT, probe screening, penalties and inoculation all evaluated in this exact environment: the comparison arms for X7 largely exist, but none is TDA.
- Another Qwen3-4B coding testbed: **CATCH**, Wang et al., arXiv 2609.39533, 30 Sep 2026 (first 100k characters, fetch summary): three loophole classes, hackable vs unhackable run gives gold labels; 8 GPUs per node, Qwen3.5-27B monitor. Useful only as a second environment.

## TDA or gradient filtering applied to RL (items 3 and 5)
- **I-PPO, Shu, Zhang, Hullman, "Learning from the Right Rollouts: Data Attribution for PPO-based LLM Post-Training", arXiv 2604.01597 v2, 24 Aug 2026** (first 100k of 113k characters, fetch summary). Per-episode PPO-loss gradient dotted with a validation SFT gradient on human-preferred CoTs; negative-score episodes dropped, rest reweighted. 1B-8B models, GSM8K/MATH-style tasks, 2-4 A100s, about 0.12 s per episode; better than PPO in 36/45 settings. Does not study reward hacking; qualitative note that negative-influence episodes carry more unfaithful reasoning. This is the closest method to X7's TDA arm and means "TDA has not been applied to RL" is no longer strictly true.
- **Hu et al., "A Snapshot of Influence", arXiv 2505.19281** (first 100k of 160k characters, fetch summary): TracIn for online RL, Iterative Influence-Based Filtering, classic control plus RLHF on 2.7B GPT-Neo; 20-67% fewer rounds, 4x in RLHF. Efficiency, not safety.
- **GradAlign, Yang et al., arXiv 2602.21492** (fetch summary): cosine of per-problem GRPO gradient with a validation gradient to select prompts; Qwen2.5-1.5B, Qwen3-8B-Base; helps with noisy rewards (41.8% vs 26.6%). Prompt-level, not rollout-level, not hacking.
- **Grift, "Detecting and Suppressing Reward Hacking with Gradient Fingerprints", arXiv 2604.16242** (first 100k of 116k characters, fetch summary; authors not captured). The nearest hacking-specific gradient method: LoRA-gradient fingerprints (5 layers, projected to 1,024 dimensions), 2-cluster K-means, a strong LM labels 16 samples per cluster; F1 about 80% vs CoT-monitor 10-40% (LLM judge reading transcripts) on in-context-loophole math/code and AR-LSAT, Qwen2.5-3B/8B, Llama3-8B. Mitigation is offline rejection fine-tuning, not online filtering during RL; 2.82 min per sample with layer selection. So "gradients beat an LLM reading transcripts at detecting hacks" has a published precedent, in a different setting, and with an expert-labelling step.
- Probe-based: **ProFIL, Parekh & Goyal, arXiv 2605.11467** ("Drop the Act", v2 1 Sep 2026; PDF fetch summary only): online probe-filtered RL for unfaithful CoT, said to beat end-to-end LLM judges. Also **Wong et al.** above (probe screening and penalty). Representation-engineering advantage modulation (arXiv 2604.01476, search snippet only: concept score from hidden states discounts the advantage).
- **Linear probes add little for verifiable reward hacking** (Dutta, LW 13 Jul 2026, fetch summary): Qwen2.5-0.5B arithmetic, probe AUC 0.998 but a string match gets 100%. A warning that simple text baselines can match fancy detectors when the hack is lexically visible; relevant because `def run_tests` is lexically visible in Aria's environment.

## SFT analogues (item 4)
- **Paulo, Jaburi, Belrose, Quirke, Biderman (EleutherAI), "The Unequal Influence of Bad Advice", arXiv 2609.37914, 29 Sep 2026** (abstract and intro read from the repo copy, `papers/em_personas` row 36; body not re-read). Verbatim abstract: "Score-based filtering can substantially enhance or attenuate EM; we find that both data-attribution scores and a black-box harmfulness score can identify consequential examples." Influence filtering works best with scores from the same model; cross-model transfer is partial. Intro: removing a chosen 20% of malign examples can lower misalignment by 5 points or raise it by 10 depending on the selection. Key point for X7: the black-box LLM score was also useful, so the SFT result does not show TDA beating an LLM; it shows both work and that TDA is model-specific. Earlier workshop version: "Mitigating Emergent Misalignment with Data Attribution" (row 73). Concept Influence (Kowal et al., arXiv 2602.14869, row 57) replaces the test gradient with a concept-vector gradient, which is the "probe/concept query" option.
- **CAFT, Casademunt et al., arXiv 2507.16795** (search-result abstract only): ablating concept directions during fine-tuning cut EM about 10x without data changes. Inoculation prompting, Wichers et al. arXiv 2510.05024 and Tan et al. arXiv 2510.04340 (search snippets only). Gradient routing, Cloud et al. 2024: only mentioned inside an inoculation paper; no URL found, not read.
- **Loracles / weight-diff meta-models for reward hacking:** searches returned nothing on this; related activation monitoring (arXiv 2603.04069, SAE plus linear classifier on reward hacking, snippet only). Not found.

## Position piece (item 6)
**Smith, Chughtai, Nanda (GDM), "Difficulties with Evaluating a Deception Detector for AIs", arXiv 2511.22662** (Nov 2025; AF post https://www.lesswrong.com/posts/zmngpxsvGbotFeQca/paper-difficulties-with-evaluating-a-deception-detector-for; abstract only, from a search snippet). It argues that detector evaluation needs confidently-labelled examples we lack. I am inferring this is the piece Jacob means; no title variant like "Difficulties with deception detectors" was found. Relevance: ground-truth labelling; Aria's environment has an execution-based label, which is a strength for X7.

## Has X7 been done?
No exact match found. Pieces exist separately: per-episode gradient-influence filtering inside PPO (I-PPO, general reasoning, not hacking), gradient-based hack detection (Grift, offline, different tasks), probe/LLM-judge/ground-truth screening in Aria's exact environment (done, no gradients), TDA-based filtering for EM in SFT (Paulo). Not found: gradient-similarity-to-a-hack-query filtering inside an RL loop, with a hacking-rate outcome, against an LLM-judge arm, on Qwen3-4B. Search recall is limited (extended searches, no site-internal search, no check of tweets or very recent preprints), so a concurrent preprint cannot be excluded. Neel's "hasn't really been applied to RL" is true for safety targets and loosely true overall, but I-PPO and Snapshot of Influence show the mechanics have been published.

## Closest prior work and the remaining gap
Closest: I-PPO (mechanism), Wong et al. (environment and baselines), Grift (gradients vs LLM monitor for hacking), Paulo et al. (TDA filtering for misalignment, SFT). Gap: a hack-targeted query (reward-hack query set or probe direction) rather than a human-preferred validation set; deciding per rollout before the update; head-to-head with an LLM-judge filter and random drop at a matched rate; measuring hacking and also monitor evasion in the same environment.

## Realistic compute (inference; none of these numbers was measured by us)
- Baseline run per Wong: 200 steps x 256 rollouts = 51,200 rollouts, 3 h on 4xH200, about $60. Hacking emerges at step 80-100, so a 120-step run (about $36) probably suffices for most arms, since the question is whether hacking is prevented.
- Per-rollout gradient scoring: I-PPO reports about 0.12 s per episode (A100, small models and shorter sequences). Qwen3-4B with LoRA-only gradients and up to 1,536 tokens per rollout is probably 0.2-0.5 s unbatched, so 256 rollouts per step cost roughly 1-2 extra minutes per step on one GPU, i.e. 50k rollouts is about 3-7 GPU-hours extra serial, plus a query-gradient refresh. Plausibly 1.5-2.5x the base run: about $90-150 per TDA run (my estimate). Cheaper variants: score only after step 40, use last-layer or few-layer LoRA gradients with random projection (as Grift), or score a subsample.
- Arms with 3 seeds each (Wong stresses seed variance): no filter about 3 x $60, LLM-judge about 3 x $65 plus judge tokens (cheap with luna), random drop about 3 x $55, TDA about 3 x $120. Total about $750-900 for full 200-step runs, about $500 with 120-step truncation. This is above the ~$100 single-experiment ask threshold in CLAUDE.md; plan a pilot (1 seed per arm, 120 steps, about $200) first. Needs 32+ CPU cores for code evaluation per the repo README, which not every RunPod H100 node offers; check.

## Design implications
- Do not start from scratch: fork ariahw/rl-rewardhacking(-ext); reuse its ground-truth, probe and LLM-judge arms as baselines; add random-drop-at-matched-rate and TDA.
- Match Wong's screening semantics (drop before advantage/gradient) or state the difference. Her note that screening does not remove correlated behavior (attempted hacking) matters for the TDA arm.
- The query set matters most: gradients of hack vs non-hack completions from the base model with run_tests-style overwrites (cheap, in-distribution) vs a probe direction (Concept Influence style). Both are lexically visible hacks, so also run a string-match baseline (Dutta); a TDA win over an LLM judge but not over regex is a weak result.
- The LLM-judge arm should be the strong version (Wong's Haiku judge was evaded and had 50-67% accuracy); report judge accuracy over training and monitor evasion for both filters, since TDA gradients are also trainable-against.
- Gradient signals are model- and checkpoint-specific (Paulo): recompute the query gradient periodically (GradAlign does so). Batch coupling in GRPO (group-normalised advantages) means per-rollout scores are approximate (I-PPO limitation).
- Seeds: at least 3 per arm; report seed-level rates, not pooled means.
- Pitfall: Form Over Content (row 58) says gradient attribution tracks answer format; a hack query may select for code shape rather than hacking intent. Include a format-matched non-hack control query.
- Label every rollout with the ground-truth hack flag, so filter precision/recall can be reported separately from the training outcome.
