# Experiment 2 (S2 pilot): planted-rule readout

Descriptive. 24 boundaries, 192 arm runs (4 arms × 2 replicates). Boundaries by rules channel: {'agents_md': 8, 'chat': 8, 'readme': 8}. Intervals: 95% bootstrap, clustered on the boundary, B = 4000, seed 20261024. Cells with fewer than 8 boundaries are marked too small. Generated by `scripts/s2_readout.py` from the released S2 rows.

## Summary

- **Planted rules were almost never broken.** Across 192 arm runs (24 boundaries × 4 arms × 2 replicates), R1 broke once (an F arm in the chat channel that edited test files and restored them), R3 never, and C never: no arm pushed or deleted a branch at all, so the consent rule was never put to the test. Zero counts don't show the absence of an effect: with 24 boundaries, a per-arm break rate up to roughly 13% could still go unseen.
- **R6 (commit prefix) is the only rule with any signal.** All 7 breaks are in S and S+I arms, all in the README channel, all at the 2 boundaries where the summary lost the rule. R6 counts only arms that made a real commit (F 27, S 26, S+R 26, S+I 25 of 48 each), so each arm's rate comes from its own committing arms: these are descriptive differences, not paired effects. Overall, S+R − S+I is −12 pp [−31, 0] and S − F is +15 pp [0, +36].
- **At those 2 boundaries the pattern is consistent with repair, but tiny.** Among committing arms, every S and S+I arm broke R6 (7/7) and every F and S+R arm followed it (0/7). Two boundaries (one GLM, one DeepSeek, both README channel) are far too few to estimate an effect, and the counts are conditioned on committing: treat it as a lead for the main run, not a result.
- **Summaries lost rules only in the README channel, and rarely.** By the retention labels (with Jacob's spot check), R1, R3 and R6 were each lost at 2 of 24 boundaries and C at 5, all README channel; the chat and AGENTS.md channels never lost a rule. So the lost-rule (repair) cells are 2–5 boundaries, too small to read.
- **Where the rule was kept, no arm broke R3, R6 or C,** and R1 broke only once (in F), so there is nothing to compare restating a kept rule against.
- **Utility: compaction's cost and the rule block's effect are both unclear.** S had lower observed reward than F (8% vs 15%; S − F −6 pp [−12, 0]) and lower f2p progress (45% vs 53%; −8 pp [−17, +1]), with intervals touching zero. Adding the rule block didn't measurably change progress: S+R − S+I is +0 pp [−6, +6] for reward and +4 pp [−2, +10] for f2p; against S, S+R − S is −5 pp [−13, +2] for f2p and −8 pp [−18, 0] for p2p, inconclusive. No arm submitted before the closing turn.
- **Sensitivity changes nothing:** no arm was flagged `would_recompact`, none had incomplete trap evidence and none had a grading error, so both sensitivity analyses equal the main one.
