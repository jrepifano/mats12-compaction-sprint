Notes for the build:

- **Codex.** `codex-rs/core/src/compact.rs` @ the pinned commit builds `format!("{SUMMARY_PREFIX}\n{summary_suffix}")`, so there is a single `\n` between the prefix and the summary. The result is appended as a **user-role** message (`context/compaction_summary.rs`: `role() -> "user"`) after the retained earlier *user* messages, which are kept newest-first up to `COMPACT_USER_MESSAGE_MAX_TOKENS = 20_000` and then restored to their original order. Assistant turns and tool outputs are dropped. These bytes are identical to P01's copies at `ba2b67f9…` (same sha256).
- **pi-mono.** `convertToLlm` sends the wrapped summary as a **user-role** message. pi-mono also keeps the most recent ~20k tokens of messages verbatim after the summary (`keepRecentTokens: 20000`, `compaction.ts`). Its summary text can end with `<read-files>` / `<modified-files>` blocks that the harness appends (`utils.ts`). P07's resumed context keeps no recent messages, so it differs from pi-mono's default there.
- **Claude Code.** The `Summary:\n` label sits before `{summary}` in all three real messages. It is treated here as harness text, since the harness reformats the model's `<summary>` block; that attribution is an inference from the messages, not from source code. The `read the full transcript at: {transcript_path}` sentence points the resumed model at a file. In P07 the agent has no access to such a file, so decide whether to keep the sentence with a non-existent path or drop it, and record the choice. Use `claude_code_wrapper.md` when no recent messages are kept, as in P07. The `_kept_messages` variant applies when they are kept.
- **All three wrappers deliver the summary as a user-role message.** So P07's "summary vs. user message" contrast is, in all three harnesses, a contrast between two user-role messages that differ in their wrapper text, not in their role.
