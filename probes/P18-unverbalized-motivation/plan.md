# P18: When Qwen3.6-27B follows a leaked answer key without saying so, do the Oracle Lens and the NLA name the leak more when it drove the answer than when it was ignored, and more than asking Qwen?

Neel's open problem ("Model forensics", `papers/_neel_brainstorm_text.txt` l. 9–10): *use tools like Oracle Lens and NLAs to find evidence of unverbalized motivations; Qwen 3.6 27B resources* (the ceselder collection, `papers/neel_brainstorm/` row 2). The setting puts the motivation in by construction: a "you gained unauthorized access; the answer is (X)" line pointing to a wrong option, the misaligned hint of Chen et al. 2025. Whether the leak *caused* an answer is measured by resampling with and without it. **The re-answer problem:** the leak is in the context, so a reader can name it just because it is there (P11; Kenney's NLA names a patched-in bridge equally whether or not the answer changes). So the test is a **use-vs-presence contrast**: the leak is present on every read prompt, and only whether it drove the answer differs.

## Notes
- **Why per-item labels at the last prompt token.** Every sample of an item shares that state, and it comes before any output. That is Neel's "read the prompt before the model says anything" test (proposals doc, Topic 2). The answer is not yet in context, so a reader can't infer the motive from "the answer equals the leak". Follow-up 2 covers the post-hoc state separately.
- **What the contrast can't separate.** Driven and ignored items differ in more than use, for example in how plausible X looks. Stratifying on no-cue confidence and the no-cue probe control handle difficulty, not everything. Follow-up 4 (one item, graded leak strength) is the within-item check.
- **Literature:** rows 65–67 and the NLA paper were read through their `INDEX.md` notes and the captured text (NLA §§ on unverbalized awareness, read verbatim). Mirtaheri & Belkin, CHIVE and Building Better AOs (excerpt) were read verbatim by the planning sub-agent; Jakkli et al. only as a search summary. Kenney's README was read verbatim, his code only skimmed (`deception_pod.py` header). The build's literature sub-agent captures Kenney's repo note and checks for newer work on readers and hint use.
