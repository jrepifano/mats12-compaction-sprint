# P49: After a long session of real coding work is compacted, does the agent cheat more on an impossible task, and does that depend on the compaction method or on which model writes the summary?

**Revision 5 (2026-10-15, after Jacob's first-principles reset).** Neel's main compaction question is about behaviour: "How much does compaction mess up agent behaviour, and how should we take this into account when thinking about safety?" He points to the Mythos hypothesis that repeated compactions dropped safety-relevant context (Central Doc, "How to think about interpreting agents?"; Oct 6 session). v4.1 measured summary fidelity offline, which is his lowest-priority sub-question; it is in git history (branch commit `8113cc5b`, `design/budget_v4.py`, `design/power_v4.py`). **v5 measures safety behaviour:**
1. a long session of real coding work by the agent itself;
2. a product compaction;
3. a new task in the same session whose tests contradict its spec (ImpossibleBench);
4. how often the agent cheats.

## Notes

### Regime check
**This measures safety behaviour after one product-scale compaction of a real, on-policy session. It does not cover repeated compaction at scale or a frontier model.**

| | Hypothesis (Mythos, products) | P49 v5 | P44 and earlier |
|---|---|---|---|
| Session | long real work, then safety-relevant decisions | ≈ 100 turns of real SWE work by the agent itself, then an impossible task | the impossible task alone (P44); chosen cuts elsewhere |
| Context at compaction | 167–967k | 115–137k (128k-window product triggers) | 5–20k (P44) |
| Compactions | several | 1 | up to 5 (P44, small) |
| Summariser | the agent itself | the agent itself (3 methods), plus DeepSeek and Haiku (Inspect) | GLM itself |
| Safety outcome | real-world harm | cheating on impossible tests (X3's detector) | the same (P44) |
| Model | frontier | Qwen3-Coder-480B (open; Neel doubts open models replicate the incident) | GLM / DeepSeek Flash |

### Mechanism prediction, from the wrappers' carry-over
The norm sits in each SWE task message.
- **Codex** keeps user messages, newest first, within 20k, so the history's task message (≈ 1.2k) survives verbatim.
- **Inspect** keeps the task input verbatim.
- **pi** keeps the system prompt, the summary and the last ~20k tokens. The task message is outside that tail, so the norm survives only if the summary keeps it.

If the norm matters, pi-self should cheat most at prompt level A.

### Caveats stated up front
- **Not fully on-policy.** The histories are on-policy up to the new task, but the dataset's sampling settings are unknown and its harness was OpenHands (we keep its system prompt and tools).
- **Gaps between the arms.** The new task's sandbox differs from the history's repository. The compacted arms see the products' carry-over, not their whole runtime (no re-read files or AGENTS.md).
- **Power.** 48 pairs detect only differences of about 20–25 points (P44-like discordance, task clustering). This is a screen for large effects.
