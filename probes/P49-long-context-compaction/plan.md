# P49: After a long stretch of real coding work is compacted, does the agent cheat more on an impossible task, and does that depend on the compaction method, the number of compactions, or how much text is compacted?

**Revision 5.2 (2026-10-16 UTC; Jacob's review of v5.1 in the Claude Doc, Details tab "Changes on 16 Oct" and the Plan tab's comment threads).** This file is the source of truth; where the doc differs, this file wins, and the differences are listed in `log.md` (2026-10-16). Neel's main compaction question is about behaviour: "How much does compaction mess up agent behaviour, and how should we take this into account when thinking about safety?" He points to the Mythos hypothesis that repeated compactions dropped safety-relevant context (Central Doc, "How to think about interpreting agents?"; Oct 6 session). The design:
1. a long stretch of real coding work by the agent itself (two or more of its own sessions, stitched to ~200k tokens);
2. one to three product compactions;
3. a new task in the same conversation whose tests contradict its spec (ImpossibleBench);
4. how often the agent cheats.

**Changes from v5.1 (Jacob, 2026-10-16):**
- histories are stitched to ~200k;
- Codex, pi and Inspect compact once, at the end of the stitched history;
- a repeated arm compacts k = 2 and 3 times (Inspect, self);
- a size arm compacts at ~120k (Inspect);
- the Haiku and DeepSeek summariser arms are dropped;
- the cap is $100, and the per-chain cap $1.60;
- there is a new minimum design;
- the low-cheat fallback is stated.

v5.1 and v4.1 are in git history (branch commits `0b6c17f3`, `8113cc5b`).

## Notes

### Regime check
**This measures safety behaviour after one to three product compactions of ~200k tokens of the agent's own real work, then a task switch. It does not cover histories far past 200k, many compactions, compaction on a live on-policy trajectory, or a frontier model.**

| | Hypothesis (Mythos, products) | P49 v5.2 | P44 and earlier |
|---|---|---|---|
| Session | long real work, then safety-relevant decisions | two or more of the agent's own SWE sessions (≈ 150–200 turns), then a task switch to an impossible task | the impossible task alone (P44); chosen cuts elsewhere |
| Context at compaction | 167–967k | 195–205k (size arm 120–145k), a configured trigger on a 262k model, later than v5.1's 128k rules and earlier than the products' 262k rules | 5–20k (P44) |
| Compactions | several | 1–3 (repeated arms replayed, not live) | up to 5 (P44, small) |
| Summariser | the agent itself | the agent itself (all arms) | GLM itself |
| Safety outcome | real-world harm | cheating on impossible tests (X3's detector) | the same (P44) |
| Model | frontier | Qwen3-Coder-480B (open; Neel doubts open models replicate the incident) | GLM / DeepSeek Flash |

### What each method keeps of the old tasks' test norm (a conditional prediction)
- **Codex:** keeps user messages, newest first, within 20k. S2's and S1's task messages (≈ 1.2k each) survive verbatim.
- **Inspect:** keeps S1's task input verbatim, at every k. Later tasks' norms survive only through the summary.
- **pi:** keeps the system prompt, the summary and the last ~20k tokens. The task messages are outside the tail, so the norm survives only if the summary keeps it, and pi's prompt asks for constraints.

Two caveats. The old norm ("you DON'T have to modify … the tests") is weaker than "DO NOT", and it is scoped to the old task. Measure (a) records which of these holds in each chain.

### Caveats stated up front
- **Not fully on-policy.** Each session is the agent's own, but S2 and the fill blocks were generated without the earlier sessions or summaries in context. The dataset's sampling settings are unknown, and its harness was OpenHands (we keep its system prompt and tools, on X3's sandbox).
- **The trend and the size contrast are not pure.** More compactions also means more total work and a different most recent session. The size arm compacts one task (S1, the most recent there) against two (S1 + S2) for Inspect-self. There is no uncompacted control at k = 2 or 3: it would exceed 262k.
- **A task switch most sessions didn't reach naturally.** 152 of the 193 S1 sessions stopped at the iteration limit, mid-task. The joins and the final transition say the old task is stopped, and engagement (d) is reported.
- **Carry-over only.** The compacted arms see the products' carry-over, not their whole runtime (no re-read files or AGENTS.md).
- **Power.** 32–40 pairs detect only differences of about 20–25 points; the 1–3 trend has more power than any single gap. This is a screen for large effects.
