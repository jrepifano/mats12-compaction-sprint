## Notes

### Regime check: what the hypothesis is about vs what P49 runs
**This is offline summary fidelity at product scale, not behaviour.**

| | Hypothesis (products, incidents) | P49 v4 | P01 and earlier probes |
|---|---|---|---|
| Trigger | window full; product rules (Codex 0.9 × window, pi window − 16k, Inspect 0.9 × window, Claude Code window − 33k) | L: product rules on a 128k window, by token count at each request; S: the same rules at a 40k trigger | chosen cut (50–90% of turns) |
| Context at compaction | 167–967k on 200k–1M windows | **L: 111.6–116.7k**; S, P40: 40k | ≈ 40k (P01 slice A), 1–6k elsewhere |
| Compactions per session | several; "the second compaction" | **1 at product scale** (no trajectory allows 2 at 128k); **3, recursive, at the scaled trigger, off-policy** | 1 (P38: 3 on ~1.5k) |
| Summariser | the agent model, product prompt and input rule | GLM or DeepSeek summarising Qwen3-Coder's trajectory, with each product's prompt and input rule | the same flash summarisers; P01 used one text rendering |
| Carry-over | product-specific | from pinned source (contract below) | partial |
| Facts | arise in the session | code-derived state (errors, tests, files) and the task's constraint | the same (P01) or inserted lines |
| Outcome | behaviour, beliefs | **summary fidelity only** | fidelity; behaviour in P07–P10, P23, P38, P44 |
| Model | frontier (Claude Mythos 5) | 2 flash summarisers (Haiku 5.5 as a follow-up) | the same flash models |

### Message contract (what each wrapper sends and keeps)

| | Codex local | pi | Inspect |
|---|---|---|---|
| Summariser input | full live history as chat messages (tool outputs truncated at 10k tokens, as Codex stores them) + the compaction prompt as a final user message | serialised text of messages before the cut, each tool result truncated to 2,000 chars; on k ≥ 2, the update prompt with `<previous-summary>` | system + task input + conversation since the last summary + prompt |
| Kept verbatim | initial context (here the OpenHands system prompt) + user messages, newest first, within 20k (the task message, median 1.2k, is always kept) | system prompt + the last ~20k tokens (cut at a valid boundary; a split turn gets a turn-prefix summary) | system + task input; no recent turns |
| Summary placed as | user message with `SUMMARY_PREFIX` | wrapped "The conversation history before this point was compacted…" | user message "[CONTEXT COMPACTION SUMMARY] …" |

- **The task constraint is always kept verbatim by Codex and Inspect.** For those two, it can only be lost from the summary, not after carry-over. In pi, the task message falls outside the ~20k tail at every compaction.
- **Tool schemas:** the OpenHands schemas are declared in the Codex and Inspect requests only if the pinned source sends tools on the compaction request. This is checked in the unit tests and logged.
