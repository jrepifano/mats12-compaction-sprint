### Offline accounting convention (frozen before the build)
- **Token count:** the DeepSeek-V4-Flash tokenizer (`60d8d707`) over message contents, tool-call names and JSON arguments, and the tool schemas once, plus 4 tokens per message. It is computed on each wrapper's stored history, e.g. after Codex's 10k-token output truncation.
- **Where the check falls:** before each assistant request.
- **Comparators,** from source: Codex `≥`, pi `>`, Inspect `>`.
- **Check against the providers:** the smoke logs both summarisers' API-reported prompt tokens at each cut beside the offline count, and the note reports the ratio. Triggers are product rules under this convention, not the products' own counts.

### Message contract (what each wrapper sends and keeps)

| | Codex local | pi | Inspect |
|---|---|---|---|
| Summariser input | full live history as chat messages (tool outputs as stored, truncated at 10k tokens) + the compaction prompt as a final user message | serialised text of messages before the cut, each tool result truncated to 2,000 chars; on k ≥ 2, the update prompt with `<previous-summary>` | system + task input + conversation since the last summary + prompt |
| Deterministic additions | none | cumulative read and modified file lists appended to the summary | none |
| Kept verbatim | initial context (here the OpenHands system prompt) + real user messages, newest first, within 20k (the task message, median 1.2k, is always kept) | system prompt + the last ~20k tokens (cut at a valid boundary; a split turn gets a turn-prefix summary) | system + task input; no recent turns |
| Summary placed as | user message with `SUMMARY_PREFIX` | wrapped "The conversation history before this point was compacted…" | user message "[CONTEXT COMPACTION SUMMARY] …" |

- **The task constraint is always kept verbatim by Codex and Inspect.** For those two, it can only be lost from the summary (secondary outcome). In pi, the task message falls outside the ~20k tail at every compaction.
- **pi's fixed 20k tail is about half of S1's context but a sixth of L's.** The pooled primary outcome measures each wrapper's whole regime, not summariser capacity alone. Results are given per wrapper, and the secondary outcome isolates the summariser.
- **Tool schemas:** the OpenHands schemas are declared in the Codex and Inspect requests only if the pinned source sends tools on the compaction request. This is checked in the unit tests and logged.
