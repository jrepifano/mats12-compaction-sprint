# P24: Does Gemma 4 31B's filler carry the specific hidden intermediate y, beyond the copied inputs it is computed from?

Follow-up to P06 ([`note.md`](../P06-filler-token-computation/note.md), item 5 and the F3 section). On Brauer et al.'s system-of-equations task, writing a donor's filler K/V into the target's filler moved Gemma 4 31B's answer toward the donor's answer on **52.0% of pairs [44.0, 60.0]**, against 5.3% for a random donor (n = 150). But the donor differed from the target only in the literal x that y is computed from (y = c1·x ± off). So the filler may carry a copy of x, which the answer position then combines with the prompt's own definition, rather than the computed y. This probe tests that x-relay account directly.

## Notes

**Why these donors.** Two readings of P06's transplant predict different things. If the filler carries y's content, any donor with a different y (X, Y, F, C) moves the answer toward the donor's, and a donor with the same y but different inputs (S) moves nothing. If the filler carries a copy of x that the answer position combines with the prompt's own definition, X and S move the answer toward the same a' (S's x' through the target's offset gives y_X), and Y, whose x is the target's, moves nothing. F changes no number token, so no account based on copied digits explains an F effect. The design is matched: X, Y and S share a' and the same \|a' − answer\|.

**What it cannot separate** (plan review r1, BLOCKING 1). A filler that relays y's whole definition (x, coefficient, offset and operator), which the answer position then evaluates, predicts the same X/Y/S/F pattern as one holding the computed y. That is computation relocated rather than performed, and no answer-level test tells them apart. Likewise, Y and S both moving shows that the filler steers through both, not that it represents both. Follow-up 2 (a downstream readout in the patched run) and P06's finding that y, but not x, is readable at the label bear on it, but do not settle it. So even outcome (c) does not show the filler computes y. It is not evidence for P17 going ahead; P17 stands on its own approval, and any extra requirement for it is Jacob's call (side-agent note, 2026-10-12, before any P24 data).

**Shift size.** Small shifts let noise score as "toward a'". The R placebo is scored against the same a', so it carries the same bias. The both-correct subset and exact matches are the cleaner secondary checks.

**Interpretation limits.** Gemma's accuracy with 100 dots is about a third (P06 F3: 0.327), so most target outputs are already wrong; the toward statistic is relative to that. A K/V-projection patch during prefill is not a completed-cache splice (P06 note, F3): later target positions attend to the injected values. A behavioural steering result like this does not show monitoring value beyond asking the model (P11's lesson).

**Plan review:** gpt-6-astra, one round (`logs/reviews/20261012-P24-plan-r1.md`), verdict GO AFTER FIXES. BLOCKING 1, the verdict exceeded what the design identifies: the outcomes now read "x-relay rejected / consistent with x-relay", full-definition relay is stated as unresolved, and P17 is no longer gated on it. BLOCKING 2, batch numerics: batching is now validated against a sequential path and reversed row order in the smoke, with an automatic fallback and a sequential rerun of unstable items (Automatic rules). MINORs: the placebo is scored against each donor's a' (not R's answer), with invalid outputs counted as not toward and Y/X as a ratio of placebo-adjusted effects; an inconclusive outcome and P06's own donor (P) for diagnosing a failed replication were added; denominators were corrected (C is 207 of the 413) and the dataset was copied and hash-checked; Brauer's fixed-input controls are now described correctly; the token counts were corrected, and the secondary sites now run as a second pass after the primary one.

**Portfolio review:** source of this probe, `logs/reviews/20261012-wave3-portfolio-r1.md` (on main), alternative 4 ("Does filler carry the specific intermediate, beyond copied inputs?", ≈ $5–10, 3–5 h). Changes from that sketch: the same-y donor (S) is matched to X and Y on a', an operator-flip donor (F) with no number token changes and P06's own donor (P) were added, and P06's random-donor control becomes the placebo scored against each donor's a'. The projection rose to ≈ $13 because n is 413 (P06: 150) and the secondary sites are kept.

**Correction (2026-10-13, after data; note review r1, finding 6).** Follow-up 2 above says the patch "overwrites only keys and values, so the residual stream at the filler itself is unchanged". That is wrong after the first patched layer. The filler's own queries attend to the injected keys and values, so the filler's attention outputs and later residuals do change. Only the projection inputs are the target's. A readout at the filler in a patched run is therefore not empty, but it mixes target and donor content. The text above is kept as published.
