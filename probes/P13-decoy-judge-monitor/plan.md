# P13: Does a decoy value a model plants in its filler computation fool Brauer et al.'s lens-reading LLM judge, and which monitor designs resist it?

Follow-up to P12 ([`note.md`](../P12-filler-conceal/note.md), including the PR #34 correction). Told "think about d at the dots instead of y" (arm CD), DeepSeek V4 Flash plants the decoy d readably on top of y; it does not remove y. A modal-number monitor then names d, not y, on 186/200 items. But that monitor named y on only 104/200 items under placebo, so P12 never showed a decoy beating a monitor worth deploying, while a ridge probe still decodes y (r 0.97). This probe tests the realistic monitor: Brauer et al.'s unsupervised pipeline (mean-subtracted logit-lens top-K, aggregated over filler cells, read by an LLM judge).

## Notes

**Why two stages.** P12 stored only full-vocabulary top-1 ids and log-probs at 12 candidate values per cell (`p12/schema.py`), not the top-K that Brauer's mean subtraction needs. Stage A is kept small (the free no-judge ranking plus about $1 of Haiku): it smoke-tests the harness during the build and is the fallback, labelled approximate, if the pod fails. Stage B is the faithful replication, and its result is the headline.

**Interpretation limits.** On this task, a text-only monitor that reads the prompt can compute y outright, so the lens monitor is a proxy for settings where it can't. The ask-the-model baseline and follow-up 2 bound this. A real monitor might also see the system prompt that requests the decoy. P12's caveat about V4 Flash's 128-token window carries over; follow-up 5 is the check.

**Literature.** Stress-Testing (row 95) and Keenan et al. (row 93) are already captured; a literature sub-agent reads Stress-Testing's appendices and Keenan's §3–5 while the build runs and checks for newer work. The searches on 2026-10-12 (three web queries plus the `papers/*/INDEX.md` and `logs/litreviews/` greps) found no test of decoys against lens-reading judges; they were read as search summaries only, so the gap is "not found in the sources searched".


**Sharing a pod with P16.** P16 (filler-selfreport) runs the same model on the same 200 items, with P12's placebo arm verbatim and the same ask-turn wording, so P13's P arm and ask turn overlap P16's turn 1 and plain ask. If both are built within the same hour, Stage B could run in P16's pod session after P16's bulk (saving one 9–45 min download, ≈ $1–7), with spend split by timed phase in each probe's ledger. P13 does not depend on it: by default it runs its own pod.
