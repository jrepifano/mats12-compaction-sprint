# P13: Does a decoy value a model plants in its filler computation fool Brauer et al.'s lens-reading LLM judge, and which monitor designs resist it?

Follow-up to P12 ([`note.md`](../P12-filler-conceal/note.md), including the PR #34 correction). Told "think about d at the dots instead of y" (arm CD), DeepSeek V4 Flash plants the decoy d readably on top of y; it does not remove y. A modal-number monitor then names d, not y, on 186/200 items. But that monitor named y on only 104/200 items under placebo, so P12 never showed a decoy beating a monitor worth deploying, while a ridge probe still decodes y (r 0.97). This probe tests the realistic monitor: Brauer et al.'s unsupervised pipeline (mean-subtracted logit-lens top-K, aggregated over filler cells, read by an LLM judge).

## Notes

**Why two stages.** P12 stored only full-vocabulary top-1 ids and log-probs at 12 candidate values per cell (`p12/schema.py`), not the top-K that Brauer's mean subtraction needs. Stage A answers the question approximately for about $7 of API with no GPU, and it starts while Stage B builds. Stage B is the faithful replication, and its result is the headline. If the pod fails, Stage A is reported, labelled as approximate.

**Interpretation limits.** On this task, a text-only monitor that reads the prompt can compute y outright, so the lens monitor is a proxy for settings where it can't. The ask-the-model baseline and follow-up 2 bound this. A real monitor might also see the system prompt that requests the decoy. P12's caveat about V4 Flash's 128-token window carries over; follow-up 5 is the check.

**Literature.** A literature sub-agent captures 2602.08877 into `papers/interp_methods/` and reads it in full while the build runs. The searches on 2026-10-12 (three web queries plus the `papers/*/INDEX.md` and `logs/litreviews/` greps) found no test of decoys against lens-reading judges. Those searches were read as search summaries only.
