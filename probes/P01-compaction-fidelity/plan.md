# P01: How often does a compaction summary drop facts, invent them, or misstate whether the task is done?

Probe version of proposal X0 (`docs/research-proposals.md`, "X0. How faithful are compaction summaries?"). *Compaction* is what an agent harness does when a session gets long: it replaces the older turns with a model-written summary and continues from it. The summary is all the agent remembers of those turns.

| **Decision it informs** | Whether compaction errors are common enough to build the compaction line on (X2: do agents trust what the summary says; X6: does a summary drop the framing that stops cheating), and which kind of error to build it on. Default if never run: X2 and X6 plant errors by guesswork, with no evidence that real summarizers make them. |
| **Closest prior work** | *Lost in Compaction* (`papers/agent_swarms/INDEX_a.md` row 37): compactors kept 17% of user-issued side constraints on average, and the compactor prompt alone moved retention by 14.5 points. *Governance Decay* (row 36): permission-rule violations went from 0% to 38% when the rule was dropped from the summary. UK AISI (row 35, §4.2.1) and Anthropic (row 15) report summaries carrying a false assumption "as established fact" and belief discontinuities after compactions, both without measurement. **Gap:** these measure retention of planted constraints. We found no measurement of whether real coding-agent summaries state facts and task status correctly when checked against what actually ran (a quick search; recall limited). |

Each harness's own rules for what to keep word for word are reproduced as well: Codex keeps recent user messages up to 20k tokens beside the summary, and OpenHands keeps the first 2 events. **Summarizers:** GLM 5.3 Flash (the agent model in slice B, so a model summarizing itself, as AISI §2.1 describes), DeepSeek V4 Flash, and Gemini 3.8 Flash. 250 transcripts × 3 prompts × 3 summarizers = 2,250 summaries, temperature 0. Reuses `emx.judge_client` (async, resumable, spend guard). |
| **Measure** | For each summary, three rates with Wilson 95% intervals, per prompt × summarizer: **(1) status misstatement**, where the summary states a test or task status that contradicts ground truth computed in code: the last test output before the cut, plus the outcome labels (`resolved` in A; in B, the tests are impossible, so "tests pass" without tampering is always false, and tampering is known from the file-based detector); **(2) dropped key facts**, the share of a per-transcript checklist missing from the summary (the task, files changed, last error, user constraints such as "DO NOT MODIFY THE TESTS", and in B whether the tests were edited); **(3) invented facts**, claims in the summary that the transcript contradicts or never supports. Status misstatements are reported in two kinds: errors against the transcript (the summarizer's fault) and repeating the agent's own false belief (e.g. "fixed" when `resolved` = 0). **Judge:** `gpt-6-luna`, which is outside every summarizer's model family. It is validated in this repo for EM grading, **not for this task**, so these numbers are unvalidated judge output. Status (1) is scored mainly by code and regex; the judge only extracts the summary's status sentence. |
| **Predictions** | (a) Status misstatements in ≥ 10% of summaries for at least one prompt × summarizer: **0.55**. Most of them repeat the agent's own wrong belief rather than misread the transcript: 0.7 given (a). (b) ≥ 30% of summaries drop at least one checklist fact: **0.7**. In slice B, fewer than half of the summaries of cheating episodes say the tests were edited: **0.5**. (c) Invented facts in ≥ 10% of summaries: **0.35**. (d) The prompt matters more than the summarizer (a larger spread in drop rate across the 3 prompts than across the 3 models): **0.5**. |
| **What each outcome changes** | Status or invention errors ≥ 10%: **continue**, graduate X0 to a study with a hand audit, and seed X2 with the real error types found. Mainly drops, few false statements: **pivot** to X6, where the question is whether a dropped fact changes behaviour. Every rate < 5%: **kill** X0 as a fidelity line, report the negative, and make compaction about trust (X2), not fidelity. |

(3) X6 Stage 0 almost for free: in slice B, whether the summary keeps the header framing. (4) A second compaction on top of the first (Anthropic saw discontinuities "especially following the second compaction"). (5) Anthropic's native API compaction as a fourth summarizer (its default prompt isn't published; Claude prices aren't in CLAUDE.md, so it would be priced first). |

## Notes

**Transcript source, an open decision for Jacob.** Recommendation: **(a) + (b), with (c) deferred.** Neither (a) nor (b) needs new permission, and both have ground truth for status claims.
- **(a) Public trajectories.** `nebius/SWE-rebench-openhands-trajectories`: 67,074 OpenHands runs by Qwen3-Coder-480B on real GitHub issues, CC-BY-4.0, with a hidden-test `resolved` label and the full tool outputs. They are long (median ~120 messages in our 40-row sample), so a real compaction would plausibly trigger. They pair naturally with the OpenHands condenser. Alternatives: `nebius/SWE-agent-trajectories` (80k SWE-agent runs, CC-BY-4.0, `target` label and test logs; older Qwen2.5/Llama3 agents) and `SWE-bench/SWE-smith-trajectories` (MIT, `resolved`; synthetic tasks). Limitation: these agents are from 2025, not current frontier models.
- **(b) Our own X3b episodes.** These are already on disk and cost nothing new to use. Status truth is exact: the tests are impossible, so a pass means tampering, and the detector says which. They are the only source that also measures whether a summary records that the agent edited the tests. Limitation: they are short (median ~15 turns), so the compaction is forced, not natural.
- **(c) Jacob's own Claude Code or Codex sessions.** These are the most realistic, but they have no test ground truth. Sending them to API summarizers and judges discloses their contents to those providers, so this needs Jacob's explicit OK. Recommended only as a later study arm.

**How faithful the prompts are to real harnesses.** The Codex, OpenHands and pi-mono prompts are the exact text in those harnesses' public repos (read on 2026-10-11). Codex may instead use OpenAI's server-side compaction for its own models, and we can't see that. Anthropic doesn't publish Claude Code's compaction prompt or its API compaction default. Community extractions exist (the X6 external review cites one, unverified), so we don't claim to reproduce Claude Code. Note that OpenHands's prompt contains a worked example saying "all tests passing", which may prime status claims. That is worth reporting either way.

**Literature.** During the build, a subagent searches for direct prior measurements of summary fidelity. A lead, not yet read: Factory.ai's post on evaluating context compression.
