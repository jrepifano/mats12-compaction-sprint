# P21: Is a model's persona in the middle of a coding-agent episode substantially different from its chat persona, and if so, is that the agent framing, the episode history, or just context priming?

Neel's open problem ([`papers/_neel_brainstorm_text.txt`](../../papers/_neel_brainstorm_text.txt), "How do model characters/personas work?"): *"To what degree is the assistant a single coherent persona versus a bunch of context specific ones? To start, I would investigate whether the chat persona and the coding agent persona are substantially different."* This probe asks the same value and personality questions in chat and mid-episode, and splits any difference into its parts.

## Notes

**Why these arms.** E − C alone cannot tell a context-specific persona from a model obeying "You are an expert software engineer" (S_sys, S) or from reading a long transcript about code (H). E − H is a bundle (system prompt, tool declarations, roles, serialization), so a residual not reproduced by S or H is labelled "framing bundle × history", not an agent persona, until F6 splits it. The thresholds are fixed now, against two yardsticks measured in the same run: paraphrase noise and the chat-persona distance between two different models.

**Known limits.** The probe question is itself a user turn, and the Assistant Axis paper finds the latest user message sets the persona, so asking may partly reset the agent to chat. A null on self-report is therefore weaker than a null on behaviour (F4). The episodes are short (median 17 turns) and on impossible tasks, so they are not ContextEcho's hours-long regime (F2, F3). Model-written-evals self-reports are stated values, not actions. DeepSeek's E arm is off-policy (F1). Qwen reads GLM's history, also off-policy.

**Not a crowded area.** Not CoT monitorability, multi-agent behaviour or eval awareness.

**Literature to capture in the build:** ContextEcho (full PDF, including its anchor-placement appendix, which may already separate the system prompt from the history), BrowserART, Tosato et al.

**Plan review** (gpt-6-astra, round 1, `logs/reviews/20261012-P21-plan-r1.md`): GO AFTER FIXES. BLOCKING findings:
1. Arms don't isolate "agent persona proper": fixed by relabelling E − H and S − C as bundles, dropping "persona proper", adding a cheap S_sys arm (role prompt alone), and naming the bundle ablations as F6.
2. Outcome rules overclaim and overlap: fixed with ordered, disjoint rules 1–4, an equivalence margin (90% CI within ±10 points), an explicit inconclusive outcome, S-reproduced value shifts now counted as "continue", and "no detected self-report shift" instead of "values transfer".
3. Weighting and uncertainty underspecified: fixed with balanced item assignment, equal item weights in every arm, paired E/H, a task → context × item bootstrap keeping repeats, and a pre-run power simulation.
4. Excluding unparsed answers can manufacture shifts: fixed with worst-case missingness bounds that every verdict must survive, and rule 1 marking a contrast "not measured" when its control arm fails.
5. Q may read the answer itself: fixed by measuring at the last prompt token before any answer, scoring against held-out half-B items, adding self-rating and answer baselines, and labelling Q descriptive unless it beats both; Q is now conditional on an API shift (MINOR 8).
6. P09's spend guard is hard-wired to P09: fixed with a P21 copy reading `EXP = "P21"`, a mocked-ledger test, explicit reasoning settings, and kept `tool_calls`.

MINOR 7 (commit a cut manifest; the 90th-percentile smoke threshold isn't in the paper) and MINOR 8 (call count, cost and wall-clock reforecast, no B200) are fixed above. The unverified-sources MINOR is handled by qualifying the gap claim and reading ContextEcho before the paid run. Cost estimate ≈ $32 (was $27), cap unchanged at $55.
